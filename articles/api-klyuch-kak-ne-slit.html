API-ключ: что это и как не слить его в GitHub

13 марта 2026 • 9 мин чтения
Поделиться:

Каждый сервис, который даёт API, требует ключ — уникальный код, по которому он понимает, кто обращается. Проблема: если ключ попадёт в чужие руки, злоумышленник сможет действовать от твоего имени, а платить будешь ты.

Что такое API-ключ

API-ключ — это длинная строка из букв и цифр. Пример:

sk-1234567890abcdefghijklmnopqrstuvwxyzABCD

Ты подставляешь её в каждый запрос, сервис проверяет: «Это ключ Ивана? Ок, выполняю». Всё, что сделано под этим ключом — записано на владельца.

Чем ключ опасен

Вот реальные сценарии, которые случались не раз:

  • Ключ к OpenAI в публичном GitHub → бот находит за 30 секунд → за ночь списывают $5000.
  • Ключ к AWS в истории коммитов → поднимают серверы для майнинга → счёт на десятки тысяч долларов.
  • Ключ к Telegram-боту → чужие рассылки от имени твоего бота.
  • Ключ к картам Google → чужие запросы маршрутов на твой аккаунт.

Публичные репозитории сканируются роботами круглосуточно. Поиск утечек — целая индустрия. Если ключ утёк — считай, он уже использован.

Среднее время до первого использования утёкшего ключа — меньше 5 минут. Отозвать его быстрее — почти невозможно.

Как НЕ надо хранить ключи

  • Прямо в коде. const API_KEY = "sk-123"; — худший вариант.
  • В публичном репозитории. Даже если удалил — остаётся в истории коммитов.
  • В HTML на сайте. Любой может открыть исходник страницы (F12 → Sources).
  • В мобильном приложении. APK легко распаковывается, ключ извлекается за минуты.

Как надо: .env файл

Ключи хранят в отдельном файле, который не попадает в репозиторий. Называется .env (от environment — окружение).

# .env
OPENAI_API_KEY=sk-1234567890abcdefg
DATABASE_URL=postgres://user:pass@localhost/db
TELEGRAM_TOKEN=7654321:AAF3xyz

В коде ключ берётся из окружения, а не из строки:

// Node.js — читаем из окружения
const apiKey = process.env.OPENAI_API_KEY;

fetch('https://api.openai.com/v1/chat/completions', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer ' + apiKey,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({ /* ... */ })
});

Для чтения .env в Node.js используют пакет dotenv:

npm install dotenv
require('dotenv').config();
// Теперь process.env содержит переменные из .env

Обязательно: .gitignore

Файл .env должен быть в первом же коммите в списке игнорируемых. Создай в корне проекта файл .gitignore:

# .gitignore
.env
.env.local
.env.*.local
node_modules/
*.log

Всё, что тут перечислено, Git не будет отслеживать. Проверь перед первым git add ..

Если ключ всё-таки утёк

Порядок действий — по секундам:

  1. Отозвать ключ. В панели сервиса (OpenAI, AWS, Google Cloud) — «Revoke» или «Delete». Это первое и самое важное.
  2. Создать новый. Старый уже не твой.
  3. Проверить счёт. Если успели накрутить — обратиться в поддержку сервиса.
  4. Убрать из репозитория. Просто удалить файл — мало, ключ остался в истории.
  5. Переписать историю Git (или проще — пересоздать репозиторий).

Пересоздать репозиторий — самый надёжный способ. История стирается полностью. Минус — теряются звёзды и форки, но для личного проекта это ерунда.

Как настроить переменные окружения на сервере

Когда проект залит на хостинг, .env файла там нет — его добавляют через панель управления. Например:

  • Vercel, Netlify — раздел Environment Variables в настройках проекта.
  • GitHub Actions — раздел Secrets → Actions.
  • Обычный VPS — файл .env на сервере, права chmod 600 (только владелец читает).

Отдельная тема: фронтенд

Запомни раз и навсегда: во фронтенде (в браузере) спрятать ключ невозможно. Любой скрипт на странице открыт для пользователя. Если ты вставляешь ключ в JS, который грузится в браузер — он уже утёк.

Что делать: ключ хранится на своём сервере, а фронтенд стучится к твоему серверу, а тот уже — к внешнему API. Своего сервера нет? Значит, ключ использовать во фронтенде нельзя. Только через бесплатные serverless-функции (Vercel Functions, Cloudflare Workers).

Что важно запомнить

  • API-ключ = пароль от твоего аккаунта в сервисе.
  • Никогда в коде, никогда в репозитории.
  • .env + .gitignore = базовая гигиена.
  • Утёк — сразу отозвать, потом разбираться.
  • Во фронтенде ключ не спрячешь — там его не должно быть вообще.
  • Даже если удалил — Git помнит. Пересоздай репозиторий.
