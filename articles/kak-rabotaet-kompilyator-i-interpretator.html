Как работает компилятор и интерпретатор

1 апреля 2026 • 10 мин чтения
Поделиться:

Ты пишешь код на Python или JavaScript, запускаешь — и он работает. А почему он работает? Кто превращает текст в действия? На этом уровне программисты делятся на тех, кто знает, и тех, кто «просто запускает». Разберёмся.

Что такое компилятор и интерпретатор

Компилятор — программа, которая переводит код с одного языка на другой (обычно — в машинный код или байт-код) целиком, заранее.

Интерпретатор — программа, которая выполняет код построчно, без предварительного перевода в машинный вид.

Разница простая:

  • Компилятор: «Прочитаю всё, переведу, потом запустим».
  • Интерпретатор: «Читаю строку — выполняю, читаю следующую — выполняю».
Компиляция — это перевод книги целиком. Интерпретация — это синхронный переводчик, который переводит по фразе.

Компилируемые языки

Примеры: C, C++, Rust, Go, Swift.

Процесс такой:

  1. Препроцессинг — обрабатываются директивы типа #include.
  2. Компиляция в объектный файл — код превращается в машинные инструкции.
  3. Линковка — несколько объектных файлов собираются в один исполняемый.
  4. Запуск — готовая программа исполняется процессором напрямую.

Плюсы:

  • Быстрый запуск и выполнение.
  • Ошибки ловятся на этапе компиляции, а не в рантайме.
  • Можно оптимизировать код на уровне процессора.

Минусы:

  • Нужно компилировать под каждую платформу (Windows, Linux, macOS).
  • Медленный цикл разработки: изменил код — перекомпилировал.

Интерпретируемые языки

Классический пример — Python, Ruby, JavaScript (в начале своей истории).

Процесс простой:

  1. Интерпретатор читает исходный код.
  2. Переводит его в промежуточное представление (байт-код).
  3. Выполняет байт-код построчно.

Плюсы:

  • Один и тот же код работает везде, где есть интерпретатор.
  • Быстрый цикл разработки: сохранил — запустил.
  • Легче писать динамический код.

Минусы:

  • Медленнее компилируемых языков.
  • Ошибки в редких ветках кода видны только в рантайме.

Промежуточный этап: байт-код

На самом деле большинство «интерпретируемых» языков сегодня не интерпретируют исходник напрямую. Сначала они компилируют его в байт-код — низкоуровневое представление, которое понимает виртуальная машина.

Python так и делает: .py → .pyc (байт-код) → исполнение в CPython VM. Именно поэтому в папке с проектом появляется __pycache__.

Java идёт дальше: .java → .class (байт-код) → исполнение в JVM. Это позволяет «написать один раз, запустить везде» — где есть JVM.

JIT-компиляция — гибрид

JIT (Just-In-Time, компиляция «на лету») — это когда код сначала работает через интерпретатор, но «горячие» участки (которые выполняются часто) компилируются в машинный код прямо во время работы.

Так работают:

  • V8 — движок JavaScript в Chrome и Node.js.
  • PyPy — альтернативный интерпретатор Python, в разы быстрее CPython.
  • .NET CLR — среда исполнения для C#.
  • JVM HotSpot — виртуальная машина Java.

Идея: медленный старт, но высокая скорость на длинной дистанции.

Что такое AST

И компилятор, и интерпретатор сначала строят AST — Abstract Syntax Tree, абстрактное синтаксическое дерево. Это представление кода в виде дерева.

Например, выражение 2 + 3 * 4 превратится в:

    +
   / \
  2   *
     / \
    3   4

AST полезен не только компиляторам. Линтеры (ESLint, Pylint), форматтеры (Prettier, Black) и транспайлеры (Babel, TypeScript) работают через AST. Если хочешь написать свой инструмент для кода — тебе тоже придётся его строить.

Типы ошибок: компиляция vs рантайм

Компилируемые языки:

  • Ошибки компиляции — синтаксис, несоответствие типов. Программа вообще не собирается.
  • Ошибки рантайма — деление на ноль, выход за границы массива. Уже после запуска.

Интерпретируемые языки:

  • Ошибки парсинга — программа не запустится.
  • Ошибки рантайма — всплывают только когда до строки дойдёт выполнение. Тот самый «а код вообще-то валидный».

Именно поэтому в Python можно целый год держать в коде функцию с опечаткой — если её никто не вызывает, ошибка не вылезет. В C++ такое не пройдёт.

Почему это важно понимать

Понимание компиляции и интерпретации помогает:

  • выбирать язык под задачу (скрипт для автоматизации vs высоконагруженный сервис);
  • понимать, почему Python медленнее C, но удобнее;
  • быстрее разбираться с ошибками — ты понимаешь, откуда они берутся;
  • лучше писать на TypeScript и знать, зачем нужен транспайлер.
Компилятор и интерпретатор — это не «противники». Современные языки берут лучшее от обоих: компилируют в байт-код, интерпретируют на старте, JIT'ят горячие участки.

Итог

Компилятор переводит код целиком, интерпретатор выполняет построчно, JIT комбинирует оба подхода. Понимание этих механизмов — не академика ради, а чтобы лучше ориентироваться в языках, инструментах и ошибках.
