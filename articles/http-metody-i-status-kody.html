HTTP-методы и статус-коды — шпаргалка с примерами

4 апреля 2026 • 10 мин чтения
Поделиться:

Каждый раз, когда ты открываешь сайт или приложение дёргает API, под капотом работает HTTP. Это протокол, на котором стоит весь современный веб. И у него есть свой язык — методы и статус-коды. Разберём их по-человечески.

Что такое HTTP-запрос

HTTP (HyperText Transfer Protocol) — протокол «запрос-ответ». Клиент отправляет запрос, сервер отвечает. Всё просто.

У запроса есть:

  • Метод — что клиент хочет сделать.
  • URL — с чем именно.
  • Заголовки — метаданные (кто, что принимает, какой формат).
  • Тело — данные (у GET обычно нет, у POST/PUT/PATCH есть).

У ответа есть:

  • Статус-код — что получилось (успех, ошибка, редирект).
  • Заголовки — метаданные ответа.
  • Тело — данные (HTML, JSON, картинка).

HTTP-методы

Метод говорит серверу, какое действие выполнить с ресурсом. Основных — пять.

GET — получить данные

Самый частый метод. Запрашивает данные, ничего не меняет. Браузер отправляет GET, когда ты открываешь страницу.

GET /articles/42 HTTP/1.1
Host: example.com
Accept: application/json

Особенности:

  • Параметры идут в URL: /articles?tag=python.
  • Не имеет тела запроса.
  • Можно кэшировать, можно перезагружать страницу без побочных эффектов.
  • Не должен ничего менять — это правило.

POST — создать новый ресурс

Используется для отправки данных на сервер: форма регистрации, новая статья, комментарий.

POST /articles HTTP/1.1
Host: example.com
Content-Type: application/json

{
  "title": "Новая статья",
  "body": "Текст..."
}

Особенности:

  • Данные идут в теле, а не в URL.
  • Повторный вызов обычно создаёт ещё один ресурс (не идемпотентен).
  • Не кэшируется браузером по умолчанию.

PUT — обновить ресурс целиком

Заменяет ресурс полностью. Если чего-то в теле не передал — на сервере это поле исчезнет.

PUT /articles/42 HTTP/1.1
Content-Type: application/json

{
  "title": "Обновлённый заголовок",
  "body": "Новый текст"
}

Идемпотентен: вызов 10 раз подряд даст тот же результат, что один раз.

PATCH — обновить часть ресурса

Обновляет только переданные поля, остальное не трогает.

PATCH /articles/42 HTTP/1.1
Content-Type: application/json

{
  "title": "Только заголовок меняем"
}

Разница с PUT: PUT заменяет, PATCH дополняет.

DELETE — удалить ресурс

DELETE /articles/42 HTTP/1.1

Тоже идемпотентен: удалил — повторный вызов вернёт «не найдено», но состояние системы то же.

Статус-коды: что сервер говорит в ответ

Статус-код — это трёхзначное число. Первая цифра говорит о категории.

  • 1xx — информационные (редко видишь).
  • 2xx — успех.
  • 3xx — редирект.
  • 4xx — ошибка на стороне клиента.
  • 5xx — ошибка на стороне сервера.

2xx — успех

КодЗначениеКогда используется
200OKСтандартный успех
201CreatedРесурс создан (после POST)
204No ContentУспех, но тело пустое (часто после DELETE)

3xx — редиректы

КодЗначениеКогда используется
301Moved PermanentlyРесурс переехал навсегда
302FoundВременный редирект
304Not ModifiedКэш актуален, тело не передаётся

301 и 302 используются при переезде сайта, 304 — для экономии трафика при кэшировании.

4xx — ошибки клиента

КодЗначениеЧто значит на практике
400Bad RequestНекорректный запрос (битый JSON, не те поля)
401UnauthorizedНе залогинен или токен просрочен
403ForbiddenЗалогинен, но нет прав
404Not FoundРесурса не существует
405Method Not AllowedТакой метод здесь не поддерживается
429Too Many RequestsRate limit — слишком часто дёргаешь API

Разница 401 vs 403: 401 — «я не знаю, кто ты», 403 — «я знаю, кто ты, но тебе нельзя».

5xx — ошибки сервера

КодЗначениеЧто значит
500Internal Server ErrorЧто-то упало в коде, конкретика в логах
502Bad GatewayПрокси не смог дозвониться до бэкенда
503Service UnavailableСервис перегружен или на обслуживании
504Gateway TimeoutБэкенд не ответил за разумное время

Если видишь 5xx — проблема на сервере, не твоя. Если 4xx — обычно твоя (или того, кто делает запрос).

Как посмотреть запросы вживую

В браузере открой DevTools (F12) → вкладка Network. Обнови страницу и увидишь все запросы:

  • метод и URL;
  • статус-код;
  • заголовки запроса и ответа;
  • тело запроса и ответа;
  • время выполнения.

Это лучший способ учиться HTTP — смотри, что реально происходит при загрузке сайта.

Практический пример с curl

curl — консольная утилита для HTTP-запросов. Примеры:

# GET-запрос к API и вывод ответа
curl https://api.example.com/users

# POST с JSON-телом и указанием Content-Type
curl -X POST https://api.example.com/users \
     -H "Content-Type: application/json" \
     -d '{"name": "Кирилл"}'

# Показать только заголовки ответа (удобно для проверки статус-кода)
curl -I https://example.com

# Отправить с авторизацией по Bearer-токену
curl -H "Authorization: Bearer TOKEN" \
     https://api.example.com/profile

Итог

HTTP — язык общения клиента и сервера. Метод говорит, что делать, статус-код — что получилось. Запомни пять методов и пять групп статусов — этого хватит на 90% задач. Если хочешь глубже — почитай про HTTPS и REST и GraphQL.
