Cookie, localStorage и sessionStorage — что выбрать

22 апреля 2026 • 10 мин чтения
Поделиться:

Если ты делаешь фронтенд, рано или поздно встанет вопрос: где хранить токен авторизации, настройки темы, содержимое корзины. Есть три стандартных способа, и у каждого свои особенности. Разберём по-честному.

Cookie

Самый старый механизм. Куки — это небольшие текстовые пары «ключ=значение», которые браузер автоматически отправляет на сервер с каждым HTTP-запросом к тому же домену.

// Установить куку
document.cookie = 'theme=dark; path=/; max-age=86400';

// Прочитать все куки (строкой)
console.log(document.cookie);   // 'theme=dark; other=value'

Писать куки вручную неудобно — обычно это делают через сервер. Сервер присылает заголовок:

Set-Cookie: session_id=abc123; HttpOnly; Secure; SameSite=Strict

Ключевые параметры:

  • HttpOnly — кука недоступна из JavaScript. Защита от XSS: украсть её нельзя.
  • Secure — отправляется только по HTTPS.
  • SameSite — защита от CSRF. Strict — не отправлять на чужие сайты, Lax — отправлять только при переходах из адресной строки, None — отправлять всегда.
  • Max-Age — время жизни в секундах.
  • Path — для каких путей отправлять.

Лимит: около 4 КБ на куку. И браузер ограничивает количество куки на домен (обычно 50).

localStorage

Хранилище пар «ключ=значение», которое живёт постоянно — пока пользователь сам не очистит. Не отправляется на сервер автоматически.

// Сохранить
localStorage.setItem('theme', 'dark');
localStorage.setItem('user', JSON.stringify({ id: 1, name: 'Кирилл' }));

// Прочитать
var theme = localStorage.getItem('theme');   // 'dark'

// Прочитать объект
var user = JSON.parse(localStorage.getItem('user'));

// Удалить
localStorage.removeItem('theme');

// Очистить всё
localStorage.clear();

Лимит: обычно 5–10 МБ. Точный объём зависит от браузера.

Работает синхронно — то есть блокирует поток при операциях. Для больших объёмов это может тормозить.

sessionStorage

Почти то же самое, что localStorage, но данные живут только пока открыта вкладка. Закрыл вкладку — данные исчезли.

sessionStorage.setItem('step', '3');
console.log(sessionStorage.getItem('step'));   // '3'

// При закрытии вкладки данные удаляются

Каждая вкладка имеет своё отдельное хранилище. Если открыть тот же сайт в двух вкладках — там будут разные sessionStorage.

Уязвимости — коротко

XSS и localStorage

Если злоумышленник может выполнить JS на твоей странице (XSS-атака) — он украдёт всё из localStorage и sessionStorage. Токены, пароли, что угодно.

Куки с HttpOnly от этого защищены: JavaScript их не видит.

CSRF и cookies

Куки автоматически отправляются с запросами. Если пользователь залогинен и заходит на чужой сайт — тот может отправить запрос на твой сервер, а куки приложатся сами. Это CSRF.

Защита — атрибут SameSite или CSRF-токены.

Пример: правильная работа с токеном

Правильный вариант — хранить токен в HttpOnly куке, которую ставит сервер:

# На сервере (Python + Flask)
from flask import make_response

@app.route('/login', methods=['POST'])
def login():
    # ... проверка логина/пароля ...

    response = make_response({'status': 'ok'})
    # Ставим токен в защищённую куку
    response.set_cookie(
        'session_token',
        'abc123xyz...',
        httponly=True,       # JS не увидит
        secure=True,         # только HTTPS
        samesite='Strict',   # защита от CSRF
        max_age=86400        # сутки
    )
    return response

Клиент про токен вообще не знает. При каждом запросе браузер сам приложит куку. Украсть нельзя ни через XSS, ни из dev tools.

Практический пример: тема сайта

Тема — не секрет, её можно спокойно хранить в localStorage:

// Кнопка переключения темы
function toggleTheme() {
  var current = localStorage.getItem('theme') || 'dark';
  var next = current === 'dark' ? 'light' : 'dark';

  localStorage.setItem('theme', next);
  document.documentElement.setAttribute('data-theme', next);
}

// При загрузке страницы — восстановить тему
function applyTheme() {
  var saved = localStorage.getItem('theme');
  if (saved) {
    document.documentElement.setAttribute('data-theme', saved);
  }
}

applyTheme();

Этот сайт так и работает — тема сохраняется в localStorage под ключом itbase_theme.

IndexedDB — если данных много

Четвёртый вариант, о котором не всегда вспоминают. IndexedDB — полноценная база данных в браузере:

  • Лимит — гигабайты.
  • Асинхронная (не блокирует поток).
  • Хранит объекты, файлы, бинарные данные.
  • Сложнее в использовании.

Используется для оффлайн-приложений, кэша больших данных, PWA. Для простых задач — избыточна.

Итог

Cookie — маленькие, отправляются на сервер, могут быть защищены от XSS через HttpOnly. localStorage — большой и постоянный, но уязвим для XSS. sessionStorage — как localStorage, но живёт только до закрытия вкладки. Токены авторизации — в HttpOnly cookie. Настройки и UI — в localStorage. Данные формы — в sessionStorage. Если данных много — IndexedDB. Не храни секреты в localStorage — их украдут при первой XSS.
