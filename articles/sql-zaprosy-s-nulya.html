SQL-запросы с нуля — SELECT, WHERE, JOIN

7 апреля 2026 • 12 мин чтения
Поделиться:

SQL — язык, на котором разговаривают с базами данных. Он старше интернета и до сих пор незаменим. Если ты работаешь с данными — SQL обязателен. Разберём базовые запросы на понятных примерах.

Если ещё не читал SQL vs NoSQL — начни с той статьи, там про виды баз в целом.

Что такое SQL и зачем

SQL (Structured Query Language) — язык для работы с реляционными базами данных. Ты пишешь запрос — база возвращает данные.

Примеры СУБД: PostgreSQL, MySQL, SQLite, MS SQL Server, Oracle. Синтаксис почти одинаковый, различия в деталях.

Наша учебная база

Представим интернет-магазин. Две таблицы:

users — пользователи:

idnameemailcity
1Кириллkirill@mail.ruМосква
2Аннаanna@mail.ruСПб
3Иванivan@mail.ruМосква

orders — заказы:

iduser_idtotalstatus
1015000paid
1111500pending
1228000paid

SELECT — выбрать данные

-- Выбрать все колонки и все строки из таблицы users
SELECT * FROM users;

-- Выбрать только name и email
SELECT name, email FROM users;

-- Выбрать и переименовать колонку в ответе (AS)
SELECT name AS имя, city AS город FROM users;

* — «все колонки». На продакшене лучше указывать явно, какие нужны — это быстрее и понятнее.

WHERE — фильтрация

-- Найти пользователя по email
SELECT * FROM users WHERE email = 'kirill@mail.ru';

-- Все пользователи из Москвы
SELECT * FROM users WHERE city = 'Москва';

-- Заказы на сумму больше 2000
SELECT * FROM orders WHERE total > 2000;

-- Заказы пользователя с id 1 со статусом paid
SELECT * FROM orders
WHERE user_id = 1 AND status = 'paid';

Операторы: =, != или <>, >, <, >=, <=, AND, OR, NOT.

IN, BETWEEN, LIKE

-- Пользователи из Москвы или СПб (IN — список значений)
SELECT * FROM users WHERE city IN ('Москва', 'СПб');

-- Заказы от 1000 до 5000 (BETWEEN — включительно с двух сторон)
SELECT * FROM orders WHERE total BETWEEN 1000 AND 5000;

-- Email, содержащий "mail" (LIKE с процентами — подстановка)
SELECT * FROM users WHERE email LIKE '%mail%';

-- Email, начинающийся с "kirill"
SELECT * FROM users WHERE email LIKE 'kirill%';

Символ % в LIKE — «любые символы». _ — «ровно один символ».

IS NULL — работа с пустыми значениями

-- Пользователи, у которых не указан город
SELECT * FROM users WHERE city IS NULL;

-- Пользователи, у которых город указан
SELECT * FROM users WHERE city IS NOT NULL;

Важно: = NULL не работает. Только IS NULL или IS NOT NULL.

ORDER BY — сортировка

-- Пользователи по алфавиту
SELECT * FROM users ORDER BY name;

-- Заказы по убыванию суммы (DESC — descending)
SELECT * FROM orders ORDER BY total DESC;

-- Сначала по городу, потом по имени
SELECT * FROM users ORDER BY city, name;

По умолчанию — по возрастанию (ASC). Для убывания — DESC.

LIMIT — ограничить количество

-- Только первые 10 заказов
SELECT * FROM orders LIMIT 10;

-- Топ-3 самых дорогих заказа
SELECT * FROM orders ORDER BY total DESC LIMIT 3;

-- Пропустить первые 20 и взять следующие 10 (пагинация)
SELECT * FROM orders LIMIT 10 OFFSET 20;

LIMIT + OFFSET — основа пагинации на сайте.

Агрегатные функции

Считают что-то по группе строк.

-- Общее количество пользователей
SELECT COUNT(*) FROM users;

-- Сумма всех заказов
SELECT SUM(total) FROM orders;

-- Средний чек
SELECT AVG(total) FROM orders;

-- Минимум и максимум
SELECT MIN(total), MAX(total) FROM orders;

GROUP BY — группировка

-- Сколько заказов у каждого пользователя
SELECT user_id, COUNT(*) AS order_count
FROM orders
GROUP BY user_id;

-- Общая сумма заказов по пользователям
SELECT user_id, SUM(total) AS total_spent
FROM orders
GROUP BY user_id
ORDER BY total_spent DESC;

Правило: в SELECT могут быть только те колонки, по которым группируешь, или агрегатные функции.

HAVING — фильтр после группировки

-- Пользователи, сделавшие больше 1 заказа
SELECT user_id, COUNT(*) AS order_count
FROM orders
GROUP BY user_id
HAVING COUNT(*) > 1;

WHERE фильтрует до группировки, HAVING — после.

JOIN — соединение таблиц

Самая важная часть SQL. Позволяет связать данные из разных таблиц.

INNER JOIN — только совпадения

-- Все заказы с именами пользователей
SELECT u.name, o.total, o.status
FROM orders o
INNER JOIN users u ON u.id = o.user_id;

Что происходит:

  • Берём таблицу orders, обозначаем её как o.
  • Присоединяем users как u.
  • Связываем по u.id = o.user_id.
  • Оставляем только строки, где есть пара.

Если у заказа не найдётся пользователь — такой заказ в результат не попадёт.

LEFT JOIN — все строки слева

-- Все пользователи и их заказы (если заказов нет — NULL)
SELECT u.name, o.id AS order_id, o.total
FROM users u
LEFT JOIN orders o ON o.user_id = u.id;

LEFT JOIN оставляет всех пользователей, даже тех, у кого нет заказов. У таких строк поля заказа будут NULL.

Сравнение JOIN'ов

ТипЧто оставляет
INNER JOINТолько строки с совпадением в обеих таблицах
LEFT JOINВсе строки из левой таблицы + совпадения из правой
RIGHT JOINВсе строки из правой + совпадения из левой
FULL OUTER JOINВсе строки из обеих таблиц

INSERT, UPDATE, DELETE — изменение данных

INSERT — добавить

-- Добавить одного пользователя
INSERT INTO users (name, email, city)
VALUES ('Олег', 'oleg@mail.ru', 'Казань');

-- Добавить сразу несколько
INSERT INTO users (name, email, city) VALUES
  ('Мария', 'maria@mail.ru', 'СПб'),
  ('Пётр', 'petr@mail.ru', 'Москва');

UPDATE — обновить

-- Обновить статус конкретного заказа
UPDATE orders
SET status = 'shipped'
WHERE id = 11;

-- Поднять всем заказчикам из Москвы скидку (всем строкам, подходящим под WHERE)
UPDATE users
SET city = 'Москва'
WHERE email LIKE '%@mail.ru';
Забыл WHERE в UPDATE — обновил все строки таблицы. Забыл WHERE в DELETE — снёс всю таблицу. Всегда проверяй WHERE перед запуском.

DELETE — удалить

-- Удалить конкретного пользователя
DELETE FROM users WHERE id = 3;

-- Удалить все отменённые заказы
DELETE FROM orders WHERE status = 'cancelled';

Порядок частей запроса

Запрос всегда пишется в таком порядке:

SELECT   -- 1. что выбрать
FROM     -- 2. откуда
JOIN     -- 3. с чем соединить
WHERE    -- 4. фильтр строк
GROUP BY -- 5. группировка
HAVING   -- 6. фильтр групп
ORDER BY -- 7. сортировка
LIMIT    -- 8. сколько вернуть

Но выполняется он в другом порядке — планировщик базы решает сам. Для понимания достаточно запомнить, что WHERE до GROUP BY, а HAVING после.

Комплексный пример

Задача: найти всех пользователей из Москвы, у которых суммарная стоимость оплаченных заказов больше 3000, и вывести их имена и суммы.

SELECT
  u.name,                       -- имя пользователя
  SUM(o.total) AS total_spent   -- суммарная сумма заказов
FROM users u
INNER JOIN orders o
  ON u.id = o.user_id           -- связываем заказы с пользователями
WHERE
  u.city = 'Москва'             -- только из Москвы
  AND o.status = 'paid'         -- только оплаченные
GROUP BY
  u.id, u.name                  -- группируем по пользователю
HAVING
  SUM(o.total) > 3000           -- фильтруем группы по сумме
ORDER BY
  total_spent DESC;             -- самые крупные сверху

Вот это уже настоящий «боевой» запрос. Такие ты будешь писать в реальной работе.

Как практиковаться

  • SQLite — встроена в Python, не нужно ничего ставить.
  • PostgreSQL в Docker — одна команда, и у тебя сервер базы.
  • Онлайн-тренажёры — sql-ex.ru, sqlbolt.com, LeetCode Database.
  • Реальные данные — выгрузи CSV в SQLite и попробуй посчитать что-то полезное.

Итог

SQL — простой, но глубокий язык. Начать можно за день: SELECT, WHERE, ORDER BY. За неделю — JOIN и GROUP BY. Дальше — практика на реальных задачах. В 90% случаев больше и не нужно.
