Зачем нужен TypeScript, если есть JavaScript

11 апреля 2026 • 10 мин чтения
Поделиться:

TypeScript — это надстройка над JavaScript, которая добавляет типы. За последние годы он стал стандартом для крупных фронтенд-проектов и серверной разработки на Node.js. Разберёмся, зачем он нужен и стоит ли его учить.

Проблема JavaScript

JavaScript — динамически типизированный язык. Это значит, что тип переменной определяется во время выполнения, а не при написании кода.

// Классический пример проблемы
function greet(user) {
  return 'Привет, ' + user.name;
}

// Где-то в коде
greet({ name: 'Кирилл' });   // работает
greet(undefined);            // упадёт: Cannot read property 'name' of undefined
greet('Кирилл');             // упадёт: user.name — undefined

Ошибку видно только когда код до неё дойдёт. В маленьком проекте это терпимо, в большом — катастрофа: одна опечатка ломает прод.

JavaScript позволяет писать код быстро, но расплата — ошибки всплывают в самый неподходящий момент.

Что делает TypeScript

TypeScript даёт возможность явно указывать типы. И проверяет их до запуска — прямо во время написания кода, в редакторе.

// Указываем, что user — объект с полем name: string
function greet(user: { name: string }): string {
  return 'Привет, ' + user.name;
}

greet({ name: 'Кирилл' });   // ок
greet(undefined);            // ошибка ещё в редакторе
greet('Кирилл');             // ошибка ещё в редакторе

Редактор (VS Code, WebStorm) сразу подчёркивает неправильные вызовы красным. Ошибка не дойдёт до прода.

Как это работает

TypeScript компилируется в JavaScript. Браузеры и Node.js не умеют исполнять TS напрямую — только JS.

# Исходник
app.ts

# После компиляции
app.js   # этот файл уже запускается

Во время компиляции TypeScript проверяет типы. Если есть ошибки — не соберётся (если включён строгий режим). Если всё ок — генерирует обычный JS.

В рантайме типов нет — они полностью исчезают. Всё превращается в чистый JavaScript.

Основные конструкции

Типы примитивов

// Явное указание типов
let name: string = 'Кирилл';
let age: number = 30;
let isActive: boolean = true;

// Автовывод — TS сам понимает тип по значению
let city = 'Москва';   // тип: string, указывать не нужно
let count = 42;        // тип: number

Массивы и объекты

// Массив чисел
const numbers: number[] = [1, 2, 3];

// Массив строк — альтернативный синтаксис
const names: Array<string> = ['Анна', 'Иван'];

// Объект
const user: { name: string; age: number } = {
  name: 'Кирилл',
  age: 30,
};

Интерфейсы и типы

Для сложных объектов описывают интерфейсы:

// Интерфейс описывает форму объекта
interface User {
  id: number;
  name: string;
  email: string;
  role?: string;   // знак вопроса — поле необязательное
}

function greet(user: User): string {
  return 'Привет, ' + user.name;
}

const kirill: User = {
  id: 1,
  name: 'Кирилл',
  email: 'kirill@mail.ru',
};

Аналогично можно через type:

type User = {
  id: number;
  name: string;
};

Разница между interface и type тонкая, на старте можно использовать любое. По общему правилу: интерфейсы — для объектов, типы — для всего остального.

Union-типы

Позволяют указать, что значение может быть одним из нескольких:

// Статус может быть только одним из этих значений
type Status = 'pending' | 'paid' | 'cancelled';

function updateStatus(status: Status) {
  // ...
}

updateStatus('paid');       // ок
updateStatus('unknown');    // ошибка компиляции

Generics

Для функций и структур, которые работают с разными типами:

// Функция возвращает первый элемент того же типа
function firstElement<T>(arr: T[]): T | undefined {
  return arr[0];
}

const num = firstElement([1, 2, 3]);      // тип: number | undefined
const str = firstElement(['a', 'b']);     // тип: string | undefined

Что TypeScript даёт на практике

  • Автодополнение в редакторе. Пишешь user. — редактор показывает список полей. Работает точно, а не наугад.
  • Рефакторинг без страха. Переименовал поле — редактор покажет все места, где его нужно поправить.
  • Ошибки до продакшена. Опечатки и несоответствия типов ловятся в момент написания кода.
  • Документация из коробки. Интерфейсы — это живая документация, которая не устаревает.
  • Уверенность при командной работе. Ты точно знаешь, что функция принимает и возвращает.

Что TypeScript не делает

  • Не ускоряет код. Это надстройка для разработки, а не оптимизация.
  • Не защищает от всех ошибок. Типы — не серебряная пуля. Логические ошибки он не поймает.
  • Не работает в браузере напрямую. Только через компиляцию в JS.

Синтаксис на примере

Сравни обычный JS и TS. Одна и та же функция.

JavaScript

function calculateTotal(items) {
  return items.reduce(function(sum, item) {
    return sum + item.price * item.quantity;
  }, 0);
}

TypeScript

interface CartItem {
  price: number;
  quantity: number;
}

function calculateTotal(items: CartItem[]): number {
  return items.reduce(function(sum, item) {
    return sum + item.price * item.quantity;
  }, 0);
}

Кода чуть больше, но теперь редактор подсказывает поля, а если передать не тот тип — сразу увидишь ошибку.

Кому стоит учить

  • Фронтенд-разработчикам. Почти все крупные проекты на React, Angular и Vue используют TS.
  • Node.js-разработчикам. NestJS, tRPC и большинство современных фреймворков — на TypeScript.
  • Тем, кто работает в команде. Типы — это контракт между разработчиками.
  • Тем, кто пишет библиотеки. TS-типы помогают пользователям вашей библиотеки.

Можно не учить, если:

  • Ты пишешь маленькие скрипты для себя.
  • Работаешь в проекте, где TS не принят.
  • Только начинаешь с JavaScript — сначала база, потом типы.

Как начать

TypeScript не нужно ставить глобально. Проще всего:

# Установить TypeScript в проект
npm install --save-dev typescript

# Создать конфиг
npx tsc --init

# Скомпилировать файл
npx tsc app.ts

Но самый простой путь для новичка — открыть официальный playground: typescriptlang.org/play. Пишешь код — сразу видишь, во что он компилируется и где ошибки. Ничего не нужно устанавливать.

Если ты уверенно пишешь на JavaScript — переход на TypeScript занимает неделю-две. Синтаксис почти тот же, добавляются типы. Дальше — вопрос привычки.

Итог

TypeScript — это JavaScript с типами. Даёт автодополнение, ловит ошибки до запуска и делает код понятнее для команды. Компилируется в обычный JS, в браузере типов нет. Учить стоит, если работаешь с большими проектами или в команде. Для мелких скриптов — не обязателен.
