Основы Linux для разработчика — базовые команды

6 апреля 2026 • 11 мин чтения
Поделиться:

Даже если ты пишешь только на Python под Windows, рано или поздно столкнёшься с Linux: сервер, CI/CD, Docker, Raspberry Pi. Без базовых команд в Linux — как без рук. Разберём минимальный набор.

Почему Linux

  • Серверы. 95% интернета работает на Linux.
  • Docker. Контейнеры — это Linux-процессы.
  • Облака. AWS, Google Cloud, Yandex Cloud — везде Linux по умолчанию.
  • Разработка. Почти все инструменты удобнее на Linux.

Навигация по файлам

Ты всегда находишься «где-то» в файловой системе. Основные команды:

# Текущая директория (где я?)
pwd

# Содержимое текущей папки
ls

# Показать скрытые файлы и подробную информацию
ls -la

# Перейти в подпапку
cd projects

# Перейти в домашнюю директорию
cd ~

# Перейти на уровень выше
cd ..

# Перейти обратно, где был до этого
cd -

# Дерево папок (если установлена утилита tree)
tree -L 2

Файловая система Linux — одна иерархия, начинается с /. Важные папки:

  • /home/user — домашняя папка пользователя.
  • /etc — конфиги системы.
  • /var/log — логи.
  • /tmp — временные файлы.
  • /usr/bin — большинство программ.

Работа с файлами

# Создать пустой файл
touch notes.txt

# Создать папку
mkdir myproject

# Создать вложенные папки одной командой
mkdir -p myproject/src/utils

# Копировать файл
cp notes.txt backup.txt

# Копировать папку рекурсивно
cp -r myproject myproject_backup

# Переместить или переименовать
mv notes.txt notes_old.txt

# Удалить файл
rm notes.txt

# Удалить папку со всем содержимым (ОСТОРОЖНО)
rm -rf myproject_backup
Команда rm -rf удаляет без подтверждения и без корзины. Одна опечатка — и ты попрощался с папкой навсегда. Особенно опасна комбинация rm -rf / или rm -rf *.

Чтение файлов

# Показать весь файл
cat notes.txt

# Показать файл с постраничной навигацией (q — выход)
less /var/log/syslog

# Показать первые 10 строк
head notes.txt

# Показать последние 10 строк
tail notes.txt

# Следить за файлом в реальном времени (Ctrl+C — выйти)
tail -f /var/log/syslog

tail -f — незаменимая команда для просмотра логов работающего приложения.

Поиск

# Найти файлы по имени
find /home -name "*.py"

# Найти и что-то сделать (например, удалить старые логи)
find /var/log -name "*.log" -mtime +30 -delete

# Искать текст внутри файлов в текущей папке
grep "ERROR" app.log

# Искать рекурсивно по всем файлам
grep -r "TODO" ./src

# Искать без учёта регистра
grep -i "error" app.log

# Показать номер строки в файле
grep -n "main" app.py

Права доступа

В Linux у каждого файла есть владелец и права. Смотреть:

ls -l script.sh
# -rwxr-xr-- 1 kirill users 512 Apr 6 12:00 script.sh

Расшифровка прав -rwxr-xr--:

  • Первый символ: - — файл, d — папка.
  • Далее три группы по 3 символа: владелец, группа, остальные.
  • r — read (чтение), w — write (запись), x — execute (запуск).

Сменить права:

# Сделать скрипт исполняемым
chmod +x script.sh

# Права 755 — владелец всё, остальные читать и запускать
chmod 755 script.sh

# Сменить владельца файла (нужен sudo)
sudo chown kirill:users script.sh

sudo — выполнение с правами администратора

# Обновить список пакетов (Ubuntu/Debian)
sudo apt update

# Установить программу
sudo apt install nginx

# Перезапустить сервис
sudo systemctl restart nginx

# Посмотреть статус сервиса
sudo systemctl status nginx

sudo — «выполнить от имени root». Без него систему менять нельзя. Используй осторожно: под root можно случайно снести что угодно.

Процессы

# Показать все процессы
ps aux

# Найти процесс по имени
ps aux | grep python

# Интерактивный просмотр процессов (q — выход)
top

# Более удобный вариант, если установлен
htop

# Убить процесс по PID
kill 12345

# Убить насильно, если не отвечает
kill -9 12345

# Убить по имени
pkill -f bot.py

Процессы живут, пока их кто-то не остановит или пока система не выключится. Хочешь, чтобы бот работал после отключения SSH — используй screen, tmux или systemd.

Сеть

# Проверить, доступен ли хост
ping google.com

# Показать IP-адреса интерфейсов
ip a

# Скачать файл
curl -O https://example.com/file.zip

# Скачать с индикатором прогресса
wget https://example.com/file.zip

# Открыть SSH-сессию с сервером
ssh user@192.168.1.10

# Копировать файл с локальной машины на сервер
scp ./bot.py user@192.168.1.10:/home/user/

Полезные мелочи

# История команд (стрелки вверх/вниз или Ctrl+R для поиска)
history

# Не прерывать команду при отключении SSH
nohup python bot.py &

# Создать архив
tar -czvf backup.tar.gz myproject/

# Распаковать архив
tar -xzvf backup.tar.gz

# Посмотреть, сколько места на диске
df -h

# Посмотреть, что занимает место в папке
du -sh *

# Выполнить несколько команд подряд
cd /var/log && tail -f syslog

Что учить дальше

  1. bash-скрипты — автоматизировать рутину.
  2. systemd — держать сервис запущенным как демон.
  3. ssh-ключи — входить на сервер без пароля, безопаснее.
  4. vim или nano — редактировать файлы прямо на сервере.
  5. Пакетные менеджеры — apt, yum, pacman — в зависимости от дистрибутива.
Не пытайся выучить Linux по книжке. Подними виртуалку или возьми VPS за 200 ₽ и делай что-то реальное. Через месяц будешь чувствовать себя как дома.

Итог

Для старта достаточно навигации, работы с файлами, прав, процессов и базовой сети. Это 90% задач, которые ты будешь делать на сервере ежедневно. Остальное придёт с практикой.
