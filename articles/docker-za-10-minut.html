Docker за 10 минут: зачем нужны контейнеры

1 марта 2026 • 9 мин чтения
Поделиться:

Классическая беда любого программиста: код работает на его компьютере, но у коллеги или на сервере — падает. Разные версии Python, разные библиотеки, разные настройки системы. Docker решает эту проблему раз и навсегда.

Идея за 10 секунд

Docker упаковывает приложение вместе со всем, что ему нужно — библиотеками, настройками, даже операционной системой (точнее, её минимальной копией) — в один контейнер. Этот контейнер можно запустить где угодно, и он будет работать одинаково.

Контейнер — это лёгкая коробка, внутри которой уже упаковано всё для работы приложения.

Контейнер vs виртуальная машина

КритерийВиртуальная машинаDocker-контейнер
Что внутриПолная ОСТолько приложение и его зависимости
РазмерГигабайтыМегабайты
ЗапускМинутыСекунды
ПотреблениеМного RAM и CPUМало — делят ядро хоста
ИзоляцияПолнаяДостаточная для большинства задач

Docker не заменяет виртуалки полностью, но в 90% случаев он легче, быстрее и удобнее.

Три главных понятия

  1. Образ (image) — шаблон, из которого создаются контейнеры. Как чертёж.
  2. Контейнер (container) — запущенный экземпляр образа. Как изделие по чертежу.
  3. Dockerfile — текстовый файл с инструкцией, как собрать образ.

Dockerfile для Python-приложения

# Берём готовый образ Python 3.12 как базу
FROM python:3.12-slim

# Указываем рабочую папку внутри контейнера
WORKDIR /app

# Копируем файл со списком зависимостей
COPY requirements.txt .

# Устанавливаем зависимости
RUN pip install --no-cache-dir -r requirements.txt

# Копируем остальные файлы проекта
COPY . .

# Команда, которая выполнится при старте контейнера
CMD ["python", "main.py"]

Построчно: берём готовую среду → переходим в папку → копируем зависимости → устанавливаем их → копируем код → говорим, что запускать. Всё.

Главные команды

КомандаЧто делает
docker build -t myapp .Собрать образ из Dockerfile в текущей папке
docker run myappЗапустить контейнер из образа
docker run -p 8080:80 myappЗапустить и пробросить порт 80 наружу как 8080
docker psСписок запущенных контейнеров
docker ps -aСписок всех, включая остановленные
docker stop имяОстановить контейнер
docker rm имяУдалить остановленный контейнер
docker imagesСписок локальных образов
docker logs имяЛоги контейнера

Зачем это нужно на практике

  • Единая среда. Все разработчики запускают одно и то же. Никаких «у меня работает».
  • Быстрый деплой. Локально собрал образ → отправил на сервер → запустил. Всё.
  • Изоляция. Приложение не сломает систему хоста.
  • Легко масштабировать. Нужно больше мощности — запусти ещё контейнеров.

Что важно запомнить

  • Docker = упаковка приложения со всем его окружением.
  • Образ — шаблон, контейнер — запущенный экземпляр.
  • Dockerfile описывает, как собрать образ.
  • Работает на любой ОС одинаково — главный плюс.
  • Начать изучать: docker build, docker run, docker ps. Остальное придёт с практикой.
