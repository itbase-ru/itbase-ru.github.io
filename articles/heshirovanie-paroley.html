Как правильно хранить пароли — хеширование и соль

16 апреля 2026 • 10 мин чтения
Поделиться:

Кажется, что хранить пароли просто: положил в базу — и всё. Но если база утечёт (а это происходит регулярно), все пароли окажутся у злоумышленника. Есть только один правильный способ — хеширование.

Почему нельзя хранить пароли как есть

Крупные утечки происходят каждый год. Когда база попадает в чужие руки, там оказываются миллионы логинов и паролей. Если пароли хранились в открытом виде — злоумышленник сразу получает доступ ко всему.

Хуже того: люди часто используют один пароль на разных сайтах. Утечка на одном проекте открывает доступ к почте, соцсетям, банку.

Правило номер один: пароль пользователя не должен храниться ни в каком виде, кроме хеша. Никаких исключений.

Что такое хеш

Хеш-функция превращает любую строку в строку фиксированной длины. При этом:

  • В одну сторону. Из пароля легко получить хеш, но из хеша пароль — почти невозможно.
  • Детерминирована. Один и тот же пароль всегда даёт один и тот же хеш.
  • Лавинна. Изменил один символ в пароле — хеш меняется полностью.

Пример:

пароль: 123456
MD5:    e10adc3949ba59abbe56e057f20f883e

пароль: 123457
MD5:    885b2c7a6bdabd0f4f9c9bbd8f3a1c1a

Из «e10adc...» вычислить «123456» математически почти невозможно. Значит, если хранить только хеш — утечка базы не раскрывает пароли.

Как проверять пароль при входе

Пользователь вводит пароль — ты хешируешь его тем же алгоритмом и сравниваешь с хешем в базе. Совпало — пароль верный.

import hashlib

def hash_password(password):
    # Простой пример — на практике так делать нельзя
    return hashlib.md5(password.encode()).hexdigest()

# При регистрации
stored_hash = hash_password('qwerty123')
# Сохраняем stored_hash в базу

# При входе
entered = input('Пароль: ')
if hash_password(entered) == stored_hash:
    print('Вход разрешён')
else:
    print('Неверный пароль')

Идея правильная, но этот код ещё небезопасен. Продолжаем.

Почему MD5 и SHA-1 не подходят

MD5 и SHA-1 — быстрые алгоритмы. Это как раз плохо. Быстрые алгоритмы легко подбираются перебором:

  • Радужные таблицы. Заранее посчитанные хеши для миллионов популярных паролей. Проверяешь свой хеш — сразу находишь пароль.
  • Брутфорс. Современная видеокарта перебирает миллиарды MD5-хешей в секунду.
  • Утечки похожих баз. Если такой же хеш уже был в другой утечке — пароль известен.

Проверь себя: хеш «e10adc3949ba59abbe56e057f20f883e» гуглится за секунду. Это MD5 от «123456».

Что такое соль

Соль (salt) — случайная строка, которая добавляется к паролю перед хешированием. У каждого пользователя — своя.

import hashlib
import os

def hash_password(password):
    # Генерируем случайную соль — 16 байт
    salt = os.urandom(16)
    # Складываем соль и пароль, считаем хеш
    hashed = hashlib.sha256(salt + password.encode()).hexdigest()
    # Возвращаем и соль, и хеш — оба надо сохранить в базу
    return salt.hex() + ':' + hashed

# У Кирилла пароль 'qwerty'
# Соль: a1b2c3d4...
# Хеш:  f5e6d7c8...

# У Анны тот же пароль 'qwerty'
# Соль: 9z8y7x6w...  (другая!)
# Хеш:  3c4d5e6f...  (тоже другая!)

Даже если у двух пользователей одинаковый пароль — в базе лежат разные хеши. Радужные таблицы бесполезны: злоумышленник не знает соль каждого пользователя.

bcrypt, scrypt, argon2

Соль решает проблему радужных таблиц, но не брутфорса. Для защиты от него нужны медленные хеш-функции. Они специально спроектированы так, чтобы считать хеш долго — сотни миллисекунд.

Пользователю это не мешает: он вводит пароль раз в день. А злоумышленнику, который хочет перебрать миллиард вариантов, — критично.

АлгоритмОсобенность
MD5, SHA-1Не использовать. Слишком быстрые
bcryptСтандарт уже 20 лет. Надёжный выбор
scryptТребует много памяти — сложнее для GPU

Правильный код на Python

Используем библиотеку bcrypt — она уже умеет и соль, и правильный алгоритм.

import bcrypt

def hash_password(password):
    # bcrypt сам генерирует соль и включает её в результат
    # encode нужен, чтобы превратить строку в байты
    return bcrypt.hashpw(password.encode(), bcrypt.gensalt())

def check_password(password, stored_hash):
    # Проверяем: подходит ли пароль к сохранённому хешу
    return bcrypt.checkpw(password.encode(), stored_hash)

# Регистрация
hashed = hash_password('qwerty123')
# В базе лежит строка типа: $2b$12$...

# Вход
if check_password('qwerty123', hashed):
    print('Вход разрешён')

if not check_password('wrongpass', hashed):
    print('Неверный пароль')

bcrypt сам заботится о соли — она встроена в итоговый хеш. Тебе не нужно её хранить отдельно.

Настройка сложности

У bcrypt есть параметр cost — сколько раз прогонять алгоритм. Каждая единица увеличивает время в два раза.

import bcrypt

# По умолчанию cost = 12 — примерно 250 мс
hashed = bcrypt.hashpw(b'secret', bcrypt.gensalt(rounds=12))

# Можно увеличить до 14 — примерно 1 секунда
hashed2 = bcrypt.hashpw(b'secret', bcrypt.gensalt(rounds=14))

Оптимально — чтобы проверка одного пароля занимала 100–500 мс. Тогда брутфорс практически невозможен, а пользователь не замечает задержки.

Типичные ошибки

  • Хранить пароль в открытом виде. Даже «временно». Даже «для отладки».
  • Использовать MD5 или SHA-1. Сегодня это считается уязвимостью.
  • Одна соль на всех. Тогда радужные таблицы снова работают.
  • Хешировать пароль на клиенте. Клиентский JS виден всем. Хеширование — только на сервере.
  • Присылать пароль в письме. Даже при восстановлении. Только ссылка со сроком жизни.
  • Логировать пароль. В логах, в трассировке, где угодно — ни в каком виде.

Восстановление пароля

Правильный алгоритм восстановления:

  1. Пользователь вводит email.
  2. Ты генерируешь одноразовый токен (случайная строка), сохраняешь его в базу с временем истечения — например, 30 минут.
  3. Отправляешь письмо со ссылкой вида example.com/reset?token=abc123.
  4. Пользователь переходит по ссылке, вводит новый пароль.
  5. Токен помечается использованным или удаляется.

Никогда не присылай сам пароль в письме. Это значит, что он хранится у тебя в открытом виде — а письма могут читать по пути.

Итог

Хранить пароли можно только в виде хеша. Используй bcrypt, scrypt или argon2 — медленные алгоритмы со встроенной солью. MD5, SHA-1 и «просто sha256» — не подходят. Восстановление — только через одноразовые токены. Если хочешь глубже про безопасность — смотри XSS, CSRF, SQL-инъекции и JWT и авторизация.
