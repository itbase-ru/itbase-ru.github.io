Асинхронность в JavaScript: промисы и async/await

11 марта 2026 • 11 мин чтения
Поделиться:

JavaScript — однопоточный язык. Это значит: в один момент выполняется ровно одна инструкция. Никаких «параллельных» задач. Если бы код умел просто «ждать» ответа от сервера, весь сайт завис бы. Поэтому придумали асинхронность.

Проблема

Представь, что ты запрашиваешь данные с сервера. Ответ может прийти через 10 миллисекунд, а может — через 10 секунд. Синхронный код остановил бы всё и ждал. Кнопки не реагировали бы, анимации замерли бы. Это неприемлемо.

Решение — асинхронный код. Он говорит браузеру: «Начни этот запрос, но не блокируй меня. Когда ответит — сообщи, и я продолжу».

Как это выглядело до промисов: колбэки

Раньше результат асинхронной операции передавали через функцию-колбэк — она вызывается, когда результат готов.

// Три вложенных запроса, каждый зависит от предыдущего
getUser(userId, function(user) {
  getOrders(user.id, function(orders) {
    getOrderDetails(orders[0].id, function(details) {
      console.log(details);
      // а если надо ещё один шаг — ещё глубже
    });
  });
});

Это называют callback hell — «ад колбэков». Читать невозможно, ошибки обрабатывать сложно.

Промис — обещание результата

Промис — это объект, который представляет будущий результат. Он в трёх состояниях:

  • pending — ожидание. Результата ещё нет.
  • fulfilled — успех. Есть значение.
  • rejected — ошибка. Есть причина.

Состояние меняется только один раз. Обратно — нельзя.

const promise = new Promise((resolve, reject) => {
  const success = true;
  if (success) {
    resolve("Данные получены");
  } else {
    reject("Что-то пошло не так");
  }
});

promise
  .then(result => console.log("Успех:", result))
  .catch(error => console.error("Ошибка:", error));

then / catch / finally

  • .then(fn) — что сделать, когда промис успешно завершился.
  • .catch(fn) — что сделать при ошибке.
  • .finally(fn) — что сделать в любом случае.
fetch('https://api.github.com/users/torvalds')
  .then(response => response.json())
  .then(data => {
    console.log('Имя:', data.name);
    console.log('Подписчиков:', data.followers);
  })
  .catch(error => console.error('Ошибка:', error))
  .finally(() => console.log('Запрос завершён'));

Цепочка читается сверху вниз — уже лучше колбэков. Но при сложной логике всё равно громоздко.

async / await — синтаксис, который выглядит синхронным

Это сахар над промисами. Код выглядит как обычный, но работает асинхронно. Два ключевых слова:

  • async перед функцией — говорит, что внутри будет асинхронный код.
  • await перед промисом — ждёт его результата, но не блокирует весь сайт.
async function showUser() {
  try {
    const response = await fetch('https://api.github.com/users/torvalds');
    const data = await response.json();

    console.log('Имя:', data.name);
    console.log('Подписчиков:', data.followers);
  } catch (error) {
    console.error('Ошибка:', error);
  } finally {
    console.log('Запрос завершён');
  }
}

showUser();

Читается почти как обычный код: получили ответ, превратили в объект, показали. Всё понятно. Но при этом браузер не зависает.

Правило: await можно использовать только внутри async-функции. За её пределами — синтаксическая ошибка.

Обработка ошибок

При работе с await ошибки ловятся обычным try / catch — как в синхронном коде.

async function getUser(id) {
  try {
    const response = await fetch('/api/users/' + id);

    if (!response.ok) {
      throw new Error('HTTP ' + response.status);
    }

    return await response.json();
  } catch (error) {
    console.error('Не удалось получить пользователя:', error);
    return null;
  }
}

Параллельно: Promise.all и Promise.allSettled

Когда несколько запросов не зависят друг от друга — их можно запустить одновременно.

// Последовательно — медленно (суммарное время всех запросов)
const user = await fetch('/api/user').then(r => r.json());
const posts = await fetch('/api/posts').then(r => r.json());
const comments = await fetch('/api/comments').then(r => r.json());

// Параллельно — быстро (время самого долгого)
const [user, posts, comments] = await Promise.all([
  fetch('/api/user').then(r => r.json()),
  fetch('/api/posts').then(r => r.json()),
  fetch('/api/comments').then(r => r.json())
]);
МетодПоведение
Promise.allЖдёт всех. Если хоть один упал — общая ошибка
Promise.allSettledЖдёт всех. Возвращает и успехи, и ошибки
Promise.raceВозвращает первый завершившийся (успех или ошибка)
Promise.anyВозвращает первый успешный

Практический пример: загрузка данных с обработкой

async function loadUsers(ids) {
  const button = document.querySelector('#loadBtn');
  button.disabled = true;

  try {
    const requests = ids.map(id =>
      fetch('/api/users/' + id).then(r => r.json())
    );

    const users = await Promise.all(requests);
    console.log('Загружено пользователей:', users.length);
    return users;
  } catch (error) {
    console.error('Не удалось загрузить:', error);
    return [];
  } finally {
    button.disabled = false;
  }
}

loadUsers([1, 2, 3, 4, 5]);

Обрати внимание: кнопка блокируется на время загрузки и всегда разблокируется в finally — даже если произошла ошибка.

Что важно запомнить

  • JavaScript однопоточный. Асинхронность — способ не блокировать браузер.
  • Промис — объект-обещание будущего результата.
  • async/await — самый удобный синтаксис. Используй по умолчанию.
  • Ошибки ловятся через try / catch.
  • Независимые запросы запускай через Promise.all — быстрее в разы.
  • Никогда не забывай await перед fetch — без него получишь промис вместо данных.
