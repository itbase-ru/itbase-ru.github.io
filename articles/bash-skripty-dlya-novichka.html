Bash-скрипты для новичка — автоматизация на Linux

25 апреля 2026 • 11 мин чтения
Поделиться:

Bash-скрипт — это обычный текстовый файл с командами, которые выполняются по очереди. Пишешь один раз — запускаешь одной командой. Идеально для рутины: сборка, деплой, бэкапы, работа с логами.

Если ещё не читал про основы Linux — начни с той статьи, там база по терминалу.

Первый скрипт

Создай файл hello.sh и вставь:

#!/bin/bash
# Это комментарий

echo "Привет, мир!"
echo "Сейчас $(date)"
echo "Ты находишься в $(pwd)"

Разбери по частям:

  • #!/bin/bash — shebang. Говорит системе: «запускай этот файл через bash».
  • echo — вывести на экран.
  • $(команда) — подставить результат команды в строку.
  • # — комментарий. Bash его игнорирует.

Запусти:

# Сделать исполняемым
chmod +x hello.sh

# Запустить
./hello.sh

Без chmod +x не запустится — система не знает, что файл можно исполнять.

Переменные

Переменные в bash создаются без ключевых слов. При обращении — знак доллара в начале.

#!/bin/bash

# Создание переменной (без пробелов вокруг =)
name="Кирилл"
age=30
project="/home/user/myapp"

echo "Привет, $name!"
echo "Тебе $age лет"
echo "Проект лежит в $project"

# Значение по умолчанию для пустой переменной — через if
if [ -z "$BACKUP_DIR" ]; then
    BACKUP_DIR="/tmp/backup"
fi
echo "Папка для бэкапа: $BACKUP_DIR"

Обрати внимание: name="Кирилл" — без пробелов. name = "Кирилл" с пробелами не сработает.

Если к переменной примыкает текст (например, склеить значение и слово) — переменную оборачивают в фигурные скобки. Иначе bash решит, что имя переменной включает и текст рядом. Но в этом примере мы обошлись обычным $name.

Аргументы командной строки

Скрипт может принимать параметры. Они доступны через $1, $2 и так далее.

#!/bin/bash

echo "Первый аргумент: $1"
echo "Второй аргумент: $2"
echo "Всего аргументов: $#"
echo "Все аргументы одной строкой: $@"
./script.sh привет мир
# Первый аргумент: привет
# Второй аргумент: мир
# Всего аргументов: 2
# Все аргументы одной строкой: привет мир

Специальные переменные: $0 — имя скрипта, $# — количество аргументов, $@ — все аргументы как список.

Условия

Проверка условий — через if и квадратные скобки:

#!/bin/bash

age=20

if [ "$age" -ge 18 ]; then
    echo "Совершеннолетний"
else
    echo "Несовершеннолетний"
fi

Основные операторы:

ОператорЗначение
-eqравно (числа)
-neне равно (числа)
-gtбольше
-ltменьше
-geбольше или равно
-leменьше или равно
=равно (строки)
!=не равно (строки)
-zстрока пустая
-nстрока не пустая

Проверка файлов и папок:

if [ -f "data.txt" ]; then
    echo "Файл существует"
fi

if [ -d "/var/log" ]; then
    echo "Папка существует"
fi

if [ ! -f "config.yml" ]; then
    echo "Файл конфига не найден — создайте его"
    exit 1
fi

-f — обычный файл, -d — папка, ! перед — отрицание.

Циклы

Два основных вида: по списку и пока условие истинно.

# Цикл по значениям
for fruit in яблоко банан груша; do
    echo "Фрукт: $fruit"
done

# Цикл по файлам в папке
for file in *.txt; do
    echo "Обрабатываю: $file"
done

# Цикл по числам
for i in {1..5}; do
    echo "Итерация $i"
done

# Пока условие истинно
counter=0
while [ $counter -lt 5 ]; do
    echo "Счётчик: $counter"
    counter=$((counter + 1))
done

{1..5} разворачивается в 1 2 3 4 5. $((выражение)) — арифметика.

Функции

#!/bin/bash

# Объявление функции
greet() {
    local name=$1   # локальная переменная — видна только внутри
    echo "Привет, $name!"
}

# Функция с возвратом значения
sum() {
    local a=$1
    local b=$2
    echo $((a + b))   # возвращаем через echo
}

# Вызов
greet "Кирилл"

result=$(sum 3 5)
echo "3 + 5 = $result"

Функции в bash не возвращают значения как в Python. Возврат — через echo, а вызывающий забирает результат через $(...).

Пример: скрипт бэкапа

Соберём всё вместе. Скрипт архивирует папку проекта в директорию бэкапов:

#!/bin/bash

# Настройки
PROJECT_DIR="/home/user/myapp"
BACKUP_DIR="/home/user/backups"
DATE=$(date +%Y-%m-%d_%H-%M)

# Проверяем, что папка проекта существует
if [ ! -d "$PROJECT_DIR" ]; then
    echo "Ошибка: папка $PROJECT_DIR не найдена"
    exit 1
fi

# Создаём папку для бэкапов, если её нет
mkdir -p "$BACKUP_DIR"

# Имя архива
FILENAME="$BACKUP_DIR/backup_$DATE.tar.gz"

# Архивируем
tar -czf "$FILENAME" "$PROJECT_DIR"

# Проверяем, что архив создан
if [ -f "$FILENAME" ]; then
    size=$(du -h "$FILENAME" | cut -f1)
    echo "Готово: $FILENAME ($size)"
else
    echo "Ошибка при создании архива"
    exit 1
fi

Запусти — получишь архив с датой в имени. Такую штуку можно поставить в cron и забыть про ручное бэкапирование.

Проверка результата команд

Каждая команда возвращает код возврата: 0 — успех, не ноль — ошибка. Он доступен в переменной $?.

cp important.txt /backup/

if [ $? -eq 0 ]; then
    echo "Копирование прошло успешно"
else
    echo "Не удалось скопировать файл"
fi

Или короче — через && и ||:

cp important.txt /backup/ && echo "Готово" || echo "Ошибка"

&& — выполнить следующее, если предыдущее успешно. || — если упало.

Отладка

Если скрипт ведёт себя странно — запусти его с флагом -x. Bash будет печатать каждую строку перед выполнением:

bash -x script.sh

Ещё вариант — добавить в начало скрипта:

#!/bin/bash
set -e   # остановиться при первой ошибке
set -u   # ругаться на неопределённые переменные
set -o pipefail   # ошибка в пайпе = ошибка всей цепочки

Эти три строки — стандарт для серьёзных скриптов. Они делают поведение более предсказуемым.

Полезные приёмы

# Проверка, что запущено с root-правами
if [ "$EUID" -ne 0 ]; then
    echo "Запусти через sudo"
    exit 1
fi

# Спросить подтверждение
read -p "Удалить файл? (y/n): " answer
if [ "$answer" = "y" ]; then
    rm important.txt
fi

# Пройти по строкам файла
while IFS= read -r line; do
    echo "Строка: $line"
done < data.txt

# Отправить письмо при ошибке
./deploy.sh || echo "Деплой упал" | mail -s "Проблема" admin@example.com

Итог

Bash-скрипт — текстовый файл с командами. Переменные без ключевых слов, условия через if [ ... ], циклы через for и while. Аргументы приходят в $1, $2. Функции возвращают результат через echo. Три флага set -euo pipefail делают скрипты предсказуемее. Идеальная задача для первого скрипта — бэкап, деплой или ротация логов.
