Как писать чистый код: 8 принципов, которые отличают новичка

7 марта 2026 • 11 мин чтения
Поделиться:

Код читают в десять раз чаще, чем пишут. Твой собственный код через месяц будет тебе чужим. Поэтому главный критерий хорошего кода — не «работает», а «понятно». Разберём восемь принципов, которые отделяют джуна от мидла.

Принцип 1. Имена говорят сами за себя

Переменная a не расскажет ничего. userAge расскажет. d в коде — это загадка для читателя.

// Плохо
const d = 7;
const u = users.filter(x => x.a > d);

// Хорошо
const inactivityDays = 7;
const activeUsers = users.filter(user => user.daysSinceLogin <= inactivityDays);

Правило простое: если имя требует комментария — имя плохое. Исключение — короткоживущие переменные в лямбдах: users.map(u => u.name) нормально.

Принцип 2. Функция делает одну вещь

Если функция называется processUser и внутри она проверяет данные, отправляет письмо, пишет в БД и логирует — это четыре функции, притворяющиеся одной.

// Плохо: одна функция — четыре задачи
function handleUser(user) {
  if (!user.email) return;
  db.save(user);
  sendEmail(user.email, 'Добро пожаловать');
  logger.info('User saved: ' + user.email);
  analytics.track('new_user');
}

// Хорошо: каждая функция делает одно
function saveUser(user) { db.save(user); }
function notifyUser(user) { sendEmail(user.email, 'Добро пожаловать'); }
function logUserSaved(user) { logger.info('User saved: ' + user.email); }

function handleUser(user) {
  if (!user.email) return;
  saveUser(user);
  notifyUser(user);
  logUserSaved(user);
  analytics.track('new_user');
}

Верхняя функция теперь читается как оглавление книги. Плюс каждая часть тестируется отдельно.

Принцип 3. DRY — не повторяйся

Don't Repeat Yourself. Если один и тот же кусок кода копируется третий раз — пора выносить в функцию. Но не в первый. Правило трёх: два раза можно, третий — выносить.

Дублирование дешевле, чем преждевременная абстракция. Иногда проще продублировать, чем построить «универсальное решение» на будущее.

Принцип 4. KISS — делай проще

Keep It Simple, Stupid. Простое решение почти всегда выигрывает у хитрого. Читаемость важнее «элегантности».

// Плохо: всё в одну строку ради краткости
const active = users.filter(u=>u.active).map(u=>({n:u.name,t:u.tags.filter(t=>t.length>3).length})).sort((a,b)=>b.t-a.t);

// Хорошо: разбито на понятные шаги
const activeUsers = users.filter(user => user.active);

const usersWithTagCount = activeUsers.map(user => ({
  name: user.name,
  tagCount: user.tags.filter(tag => tag.length > 3).length
}));

const sorted = usersWithTagCount.sort((a, b) => b.tagCount - a.tagCount);

Строк больше, но каждая читается за секунду.

Принцип 5. YAGNI — тебе это не понадобится

You Aren't Gonna Need It. Не пиши код «на будущее». 90% этого будущего не наступит, а поддерживать заготовки придётся уже сейчас.

Пример: пишешь блог — не начинай с «поддержки 12 языков и мультипользовательского режима». Начни с одной статьи на русском. Добавишь остальное, если понадобится.

Принцип 6. Ранний выход вместо вложенности

Вложенные if — пожиратели внимания. Правило: если условие можно проверить в начале — проверь и выйди.

// Плохо: три уровня вложенности
function getDiscount(user) {
  if (user) {
    if (user.isActive) {
      if (user.orders > 5) {
        return 15;
      }
    }
  }
  return 0;
}

// Хорошо: ранние выходы
function getDiscount(user) {
  if (!user) return 0;
  if (!user.isActive) return 0;
  if (user.orders <= 5) return 0;
  return 15;
}

Каждое условие — понятно и независимо. Легко добавлять новые правила.

Принцип 7. Комментарии объясняют «почему», а не «что»

Плохой комментарий — тот, что повторяет код. Хороший — объясняет причину решения.

// Плохо: повторяет код
// Увеличиваем счётчик на 1
counter++;

// Хорошо: объясняет причину
// Работаем с 1-индексацией, чтобы совпадало с нумерацией в UI
counter++;

Если код требует много комментариев — вероятно, его стоит переписать, а не закомментировать.

Принцип 8. Правила оформления — не для красоты

Отступы, пустые строки, длина строки — не «придирки». Это визуальная иерархия. Глаз находит нужное за секунды вместо минут. Для JavaScript есть инструмент Prettier — он форматирует код автоматически по единым правилам. Установил — забыл о спорах об отступах.

Что важно запомнить

  • Код пишут для людей, а не для машин.
  • Имя важнее комментария. Хорошо названная переменная экономит строку объяснений.
  • Одна функция — одна задача.
  • DRY — не дублируй. KISS — будь проще. YAGNI — не строй на будущее.
  • Ранний выход убивает вложенность.
  • Один вечер на освоение Prettier окупается через неделю.
