Многопоточность в Python — GIL и потоки

12 апреля 2026 • 11 мин чтения
Поделиться:

У Python репутация «медленного языка для потоков». Правда — сложнее. В этой статье разберём, что такое GIL, почему threading часто не ускоряет код и в каких случаях потоки всё-таки полезны.

Потоки и процессы — в чём разница

Прежде чем говорить про GIL, надо понять разницу между двумя способами параллельного выполнения.

КритерийПотоки (threads)Процессы (processes)
Общая памятьДаНет, каждый со своей
ЗапускБыстроМедленнее
Обмен даннымиПросто (общие переменные)Через очереди и файлы
Ускорение CPU-задачВ Python — нетДа

Потоки живут внутри одного процесса и делят память. Процессы изолированы друг от друга и работают действительно параллельно.

Что такое GIL

GIL (Global Interpreter Lock) — глобальная блокировка интерпретатора Python. Она означает простое правило: в один момент времени только один поток может выполнять Python-код.

Представь комнату с одним микрофоном. Даже если в комнате десять человек, говорить может только тот, у кого микрофон. Остальные ждут своей очереди.

GIL — не баг, а осознанный выбор разработчиков CPython. Он делает работу с памятью простой и безопасной, но лишает потоки возможности ускорять вычисления.

Проверим на практике

Напишем код, который считает сумму чисел в цикле — это чистая работа процессора. Запустим его последовательно и в потоках.

import threading
import time

def count_sum(n):
    # Просто крутим цикл и считаем сумму — тяжёлая работа для процессора
    total = 0
    for i in range(n):
        total += i
    return total

# Последовательно: сначала первая задача, потом вторая
start = time.time()
count_sum(10_000_000)
count_sum(10_000_000)
print('Последовательно:', round(time.time() - start, 2), 'сек')

# В потоках: запускаем обе одновременно
start = time.time()
t1 = threading.Thread(target=count_sum, args=(10_000_000,))
t2 = threading.Thread(target=count_sum, args=(10_000_000,))
t1.start()
t2.start()
t1.join()   # ждём завершения первого потока
t2.join()   # и второго
print('В потоках:', round(time.time() - start, 2), 'сек')

Если запустишь — увидишь одно и то же время. Потоки не помогли, потому что GIL не давал им работать одновременно.

А теперь — задача на ожидание

Возьмём другую задачу: имитируем скачивание файлов. Тут мы не работаем процессором, а ждём ответа от сети.

import threading
import time

def download(name, seconds):
    print(name, 'начал скачивание')
    # Имитируем ожидание ответа от сети
    time.sleep(seconds)
    print(name, 'завершил')

# Последовательно
start = time.time()
download('file1', 1)
download('file2', 1)
download('file3', 1)
print('Последовательно:', round(time.time() - start, 2), 'сек')   # ~3 сек

# В потоках
start = time.time()
threads = []
for i in range(1, 4):
    t = threading.Thread(target=download, args=('file' + str(i), 1))
    threads.append(t)
    t.start()

for t in threads:
    t.join()

print('В потоках:', round(time.time() - start, 2), 'сек')   # ~1 сек

Тут потоки дают трёхкратное ускорение. Потому что во время ожидания сети GIL освобождается — и другие потоки могут работать.

GIL не мешает ожиданию. Он мешает только вычислениям.

Когда использовать threading

Threading полезен для задач ввода-вывода (I/O):

  • Скачивание файлов из сети.
  • Работа с API нескольких сервисов параллельно.
  • Чтение и запись множества файлов.
  • Работа с базой данных, где запросы долгие.

Во всех этих задачах программа большую часть времени ждёт — и потоки успевают делать работу друг друга.

Когда нужны процессы

Для вычислений — обработки изображений, математики, ML — нужен модуль multiprocessing. Он запускает отдельные процессы Python, каждый со своим GIL. Это работает по-настоящему параллельно.

from multiprocessing import Pool

def count_sum(n):
    total = 0
    for i in range(n):
        total += i
    return total

if __name__ == '__main__':
    # Запускаем 4 процесса одновременно
    with Pool(4) as pool:
        results = pool.map(count_sum, [10_000_000] * 4)
    print('Готово, результатов:', len(results))

Важно: if __name__ == '__main__': — обязательная защита. Без неё процессы начнут запускаться заново и создадут бесконечный цикл.

Когда нужен asyncio

Третий путь — асинхронность через asyncio. Она тоже хорошо работает с I/O, но по-другому: не запускает новые потоки, а переключает задачи внутри одного потока.

import asyncio

async def download(name, seconds):
    print(name, 'начал')
    await asyncio.sleep(seconds)   # не блокирует другие задачи
    print(name, 'готов')

async def main():
    # Запускаем три задачи одновременно
    await asyncio.gather(
        download('file1', 1),
        download('file2', 1),
        download('file3', 1),
    )

asyncio.run(main())   # займёт ~1 секунду

Asyncio легче потоков: нет накладных расходов на переключение контекста. Но требует асинхронных библиотек — обычный requests там не работает.

Что выбрать

ЗадачаИнструмент
Много вычисленийmultiprocessing
Много сетевых запросовasyncio или threading
Работа с файламиthreading
Простые скриптыбез параллельности

Не пытайся всё распараллелить. Часто последовательный код быстрее и проще — а выгода от параллельности не окупает сложности.

Важно про Python 3.13

В новых версиях Python (3.13+) появился экспериментальный режим без GIL. Его можно включить отдельной сборкой. Это большой шаг — но пока он нестабилен и не для продакшена. Следи за развитием, но пиши код так, будто GIL всё ещё есть.

Итог

GIL мешает потокам ускорять вычисления, но не мешает при ожидании. Для I/O — threading или asyncio. Для CPU — multiprocessing. Понимание GIL спасает от классической ошибки новичка: «запущу вычисления в потоках и станет быстрее».
