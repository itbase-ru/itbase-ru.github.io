Что такое CORS и почему браузер блокирует запросы

17 апреля 2026 • 10 мин чтения
Поделиться:

Классическая ошибка, которую видел каждый веб-разработчик: запрос не проходит, в консоли красное «has been blocked by CORS policy». Что это и почему браузер так делает — разбираем по шагам.

Откуда взялась проблема

Представь, что ты залогинен в свой банк. Открываешь другую вкладку — на фишинговом сайте. Тот сайт выполняет в фоне запрос:

fetch('https://bank.com/api/transfer', {
  method: 'POST',
  body: JSON.stringify({ to: 'attacker', amount: 100000 }),
  credentials: 'include'   // приложить куки банка
});

Если браузер не защищён, куки банка автоматически прикладываются к запросу. Банк считает его «легальным» и выполняет перевод. Ты ничего не заметил.

Именно от этого защищает браузер. Правило называется Same-Origin Policy (политика одного источника).

Что такое «один источник»

Origin (источник) — это комбинация трёх вещей:

ЧастьПример
Протоколhttps://
Доменexample.com
Порт443 (по умолчанию)

Два URL — «один источник», если у них совпадают все три части. Если хоть одна отличается — источники разные.

  • https://site.com и https://site.com/api — один источник.
  • http://site.com и https://site.com — разные (протокол отличается).
  • site.com и api.site.com — разные (домен отличается).
  • site.com и site.com:8080 — разные (порт отличается).

Если запрос идёт на другой origin — браузер по умолчанию его блокирует. Если сервер явно не разрешит — то есть не отправит заголовки CORS.

Что такое CORS

CORS (Cross-Origin Resource Sharing) — механизм, при котором сервер явно разрешает запросы с определённых доменов.

Работает так: браузер перед запросом или вместе с ним отправляет заголовок Origin с адресом сайта-источника. Сервер может ответить:

Access-Control-Allow-Origin: https://example.com

Это значит: «разрешаю запросы с этого домена». Если в ответе такого заголовка нет — браузер блокирует ответ.

Простой и предварительный запросы

Есть два вида CORS-запросов.

Простой запрос

Отправляется сразу, без дополнительной проверки. Условия:

  • Метод — GET, POST или HEAD.
  • Заголовки только «простые» (без Authorization, Content-Type: application/json и др.).
  • Content-Type — только text/plain, multipart/form-data или application/x-www-form-urlencoded.

Всё, что сложнее — уже не «простой» запрос.

Предварительный запрос (preflight)

Если запрос «сложный» — метод PUT или DELETE, или заголовок Content-Type: application/json — браузер сначала отправляет OPTIONS-запрос, чтобы узнать, разрешён ли основной.

OPTIONS /api/users HTTP/1.1
Origin: https://example.com
Access-Control-Request-Method: POST
Access-Control-Request-Headers: content-type, authorization

Сервер отвечает:

HTTP/1.1 204 No Content
Access-Control-Allow-Origin: https://example.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: content-type, authorization
Access-Control-Max-Age: 86400

Только после этого браузер отправит основной POST. Если preflight провалился — запрос вообще не уйдёт.

Access-Control-Max-Age: 86400 — кэшируем это разрешение на сутки. Следующие запросы в этот период не будут вызывать preflight.

Как настроить CORS на сервере

Node.js (Express)

const express = require('express');
const cors = require('cors');
const app = express();

// Разрешить запросы только с одного домена
app.use(cors({
  origin: 'https://example.com',
  methods: ['GET', 'POST', 'PUT', 'DELETE'],
  allowedHeaders: ['Content-Type', 'Authorization'],
  credentials: true   // разрешить куки
}));

app.get('/api/users', function(req, res) {
  res.json([{ id: 1, name: 'Кирилл' }]);
});

app.listen(3000);

Python (FastAPI)

from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI()

app.add_middleware(
    CORSMiddleware,
    allow_origins=['https://example.com'],
    allow_methods=['GET', 'POST', 'PUT', 'DELETE'],
    allow_headers=['Content-Type', 'Authorization'],
    allow_credentials=True,
)

@app.get('/api/users')
def get_users():
    return [{'id': 1, 'name': 'Кирилл'}]

Просто через заголовки

Если у тебя не фреймворк, а голый сервер — просто добавь заголовки к ответу:

from http.server import HTTPServer, BaseHTTPRequestHandler

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        self.send_response(200)
        # Разрешаем запросы с любого домена (для теста!)
        self.send_header('Access-Control-Allow-Origin', '*')
        self.send_header('Content-Type', 'application/json')
        self.end_headers()
        self.wfile.write(b'{"message": "ok"}')

HTTPServer(('localhost', 8000), Handler).serve_forever()

Опасность звёздочки

Видел Access-Control-Allow-Origin: *? Это «разрешить всем». Удобно для отладки, но опасно в проде:

  • Любой сайт может дёргать твой API. В том числе недружественный.
  • Куки не передаются. С звёздочкой параметр credentials запрещён по спецификации.

Правильный подход — явный список разрешённых доменов:

const allowedOrigins = [
  'https://example.com',
  'https://www.example.com',
  'https://admin.example.com'
];

app.use(cors({
  origin: function(origin, callback) {
    // Запросы без origin (curl, мобильные приложения) пропускаем
    if (!origin) return callback(null, true);

    if (allowedOrigins.includes(origin)) {
      callback(null, true);   // разрешаем
    } else {
      callback(new Error('CORS запрещён'));   // блокируем
    }
  }
}));

Почему это только браузерная защита

Важно понимать: CORS работает только в браузере. Если запрос делает не браузер, а:

  • Postman
  • curl
  • мобильное приложение
  • серверный скрипт

— CORS вообще не проверяется. Эти клиенты спокойно делают любые запросы. CORS защищает только пользователя за браузером от других сайтов, которые могли бы действовать от его имени.

CORS — не защита API от чужих. Это защита браузера пользователя от скриптов на чужих сайтах.

Что делать при разработке

Когда фронт на localhost:3000, а бэк на localhost:8000 — это разные origin. Браузер блокирует. Три решения:

  1. Настроить CORS на бэке — правильный путь.
  2. Проксировать запросы через dev-сервер. Фронт и бэк оказываются на одном origin.
  3. Отключить проверку в браузере. Работает только для отладки, не для прода. Просто не делай так.

Итог

CORS — механизм, который защищает пользователя от скриптов с чужих сайтов. Работает только в браузере. Сервер явно указывает, каким доменам разрешены запросы — через заголовки Access-Control-Allow-*. Звёздочка удобна для отладки, но не для продакшена. Если видишь «blocked by CORS» — проблема на сервере, а не в браузере.
