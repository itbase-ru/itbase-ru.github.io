ООП простыми словами — классы, объекты, наследование

28 марта 2026 • 10 мин чтения
Поделиться:

ООП — объектно-ориентированное программирование. Звучит как что-то академическое, но на деле это просто способ organising код вокруг сущностей, а не вокруг функций.

Разберём на пальцах.

Проблема, которую решает ООП

Представь, ты пишешь программу для интернет-магазина. У тебя есть пользователи, товары, заказы. Если писать «функционально», получится куча разрозненных функций:

def create_user(name, email, balance):
    return {'name': name, 'email': email, 'balance': balance}

def add_balance(user, amount):
    user['balance'] += amount

def get_user_balance(user):
    return user['balance']

Работает. Но когда сущностей становится много, а логики — ещё больше, такой код превращается в кашу. ООП предлагает собрать данные и функции, которые с ними работают, в одно целое.

Класс и объект

Класс — это чертёж. Объект — это то, что построено по чертежу.

Класс User описывает, что вообще есть у пользователя. Объект kirill — конкретный пользователь с конкретными данными.

class User:
    def __init__(self, name, email, balance=0):
        self.name = name
        self.email = email
        self.balance = balance

    def add_balance(self, amount):
        self.balance += amount

    def __str__(self):
        return f'{self.name} ({self.email}), баланс: {self.balance}'

kirill = User('Кирилл', 'k@example.com')
kirill.add_balance(500)
print(kirill)

Что тут происходит:

  • __init__ — это конструктор, вызывается при создании объекта.
  • self — ссылка на сам объект. Через него метод обращается к своим данным.
  • add_balance — метод, который работает с данными конкретного объекта.

Принцип 1. Инкапсуляция

Инкапсуляция — это про то, что внутреннее устройство объекта скрыто, а снаружи доступно только то, что нужно.

Пример: банкомат. Ты не лезешь в его внутренности, чтобы узнать баланс — ты нажимаешь кнопку. Аналогично: класс прячет свои внутренние поля и показывает только удобные методы.

class BankAccount:
    def __init__(self):
        self._balance = 0

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError('Сумма должна быть положительной')
        self._balance += amount

    @property
    def balance(self):
        return self._balance

Напрямую изменить _balance в обход проверок нельзя — только через deposit. Это и есть инкапсуляция.

Принцип 2. Наследование

Наследование позволяет создать новый класс на основе существующего, добавив или переопределив поведение.

class Animal:
    def __init__(self, name):
        self.name = name

    def sound(self):
        return '...'

class Dog(Animal):
    def sound(self):
        return 'Гав'

class Cat(Animal):
    def sound(self):
        return 'Мяу'

Dog и Cat наследуются от Animal. Они автоматически получают поле name и могут переопределять метод sound.

Наследование хорошо, когда между классами есть отношение «является»: собака — это животное, кот — это животное.

Принцип 3. Полиморфизм

Полиморфизм — это когда разные объекты реагируют на один и тот же вызов по-разному.

animals = [Dog('Рекс'), Cat('Барсик')]

for animal in animals:
    print(animal.name, '-', animal.sound())

Мы вызываем sound() у каждого — а поведение разное. Программе не нужно знать, кто именно перед ней: она просто вызывает метод.

Именно это позволяет писать гибкий код: добавляешь нового зверя — ничего в цикле менять не надо.

Принцип 4. Абстракция

Абстракция — это про то, что мы описываем только важное, отбрасывая детали. В коде это часто выражается абстрактными классами или интерфейсами.

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

class Circle(Shape):
    def __init__(self, r):
        self.r = r

    def area(self):
        return 3.14 * self.r ** 2

class Square(Shape):
    def __init__(self, side):
        self.side = side

    def area(self):
        return self.side ** 2

От Shape нельзя создать объект — это абстракция. Но она задаёт контракт: «любая фигура обязана уметь считать площадь».

Когда ООП не нужно

ООП — не серебряная пуля. Для скрипта на 50 строк или утилиты из одной функции классы будут только мешать. ООП раскрывается в больших проектах, где есть много сущностей и сложное взаимодействие.

Хороший признак того, что пора вводить класс: у тебя несколько функций принимают одни и те же данные и передают их друг другу.

Итог

ООП — это про то, чтобы держать данные и код рядом, прятать внутренности, переиспользовать поведение через наследование и уметь работать с разными объектами одинаково. Четыре принципа — четыре способа не утонуть в сложности.
