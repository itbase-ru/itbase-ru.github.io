Алгоритмы и структуры данных — с чего начать

31 марта 2026 • 11 мин чтения
Поделиться:

«Учить ли алгоритмы?» — вопрос, который рано или поздно задаёт себе каждый программист. И ответ всегда один: да, но не так, как на собеседованиях в FAANG. Разберёмся, что реально нужно.

Зачем программисту алгоритмы

Многие думают, что алгоритмы — это что-то из университета, что не пригодится в реальной работе. Это миф. Просто на практике ты не пишешь сортировку сам — её уже написали. Но ты выбираешь, как хранить данные, и этот выбор влияет на скорость и удобство всей программы.

Алгоритмы — это не про то, как писать сортировку. Это про то, как понимать, почему один код работает за миллисекунду, а другой — за минуту.

Сложность алгоритмов: O-большое

Когда говорят «этот алгоритм O(n²)» — это про то, как растёт время работы при росте данных. Читается «о-большое от эн-квадрат».

НотацияНазваниеНаглядно
O(1)КонстантнаяВзять элемент по индексу
O(log n)ЛогарифмическаяБинарный поиск
O(n)ЛинейнаяПройти по массиву один раз
O(n log n)ЛинеарифмическаяБыстрая сортировка
O(n²)КвадратичнаяСортировка пузырьком
O(2ⁿ)ЭкспоненциальнаяПеребор всех подмножеств

Пример: если поиск по массиву из 1000 элементов занимает 1 мс, то O(n²)-алгоритм на 1 000 000 элементов — это уже минуты. А O(log n) на тех же данных — доли миллисекунды.

Базовые структуры данных

Массив (Array)

Непрерывный блок памяти, элементы лежат по порядку. Быстрый доступ по индексу — O(1). Но вставка в середину — O(n), потому что нужно сдвинуть остальные.

numbers = [1, 2, 3, 4, 5]
print(numbers[2])  # 3, за константное время
numbers.insert(0, 0)  # вставка в начало — O(n)

В Python список — это динамический массив. В JavaScript — тоже (там ещё есть типизированные массивы).

Связный список (Linked List)

Элементы не лежат подряд, а ссылаются друг на друга. Вставка и удаление — быстро, поиск — медленно, потому что нужно идти по цепочке.

class Node:
    def __init__(self, value):
        self.value = value
        self.next = None

head = Node(1)
head.next = Node(2)
head.next.next = Node(3)

Используется редко, но важно знать как основу для более сложных структур — стеков, очередей.

Хеш-таблица (Hash Table)

Структура «ключ → значение». В Python — dict, в JavaScript — Object и Map, в Java — HashMap.

user = {'name': 'Кирилл', 'age': 30}
print(user['name'])  # доступ за O(1)

Это самая используемая структура в реальной работе. Кэши, счётчики, индекс — всё это хеш-таблицы. Знай её досконально.

Стек и очередь

Стек — LIFO (Last In, First Out). Как стопка тарелок: последняя положенная — первая берётся.

Очередь — FIFO (First In, First Out). Как очередь в магазине: первый пришёл — первый вышел.

from collections import deque

stack = []
stack.append(1)
stack.append(2)
stack.pop()  # 2 — LIFO

queue = deque()
queue.append(1)
queue.append(2)
queue.popleft()  # 1 — FIFO

Дерево (Tree)

Иерархическая структура. Классика — бинарное дерево поиска, где левый потомок меньше родителя, правый — больше.

Используется в файловых системах, базах данных (B-tree для индексов), DOM в браузере. Поиск — O(log n), если дерево сбалансировано.

Граф (Graph)

Набор вершин и связей между ними. Соцсети, карты дорог, зависимости пакетов, рекомендации — всё это графы.

Основные алгоритмы: обход в ширину (BFS), обход в глубину (DFS), поиск кратчайшего пути (Дейкстра).

Базовые алгоритмы

Бинарный поиск

Ищет элемент в отсортированном массиве за O(log n). Делит диапазон пополам и сравнивает середину с искомым:

def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

На 1 000 000 элементов нужно всего 20 сравнений. Наглядно? Очень.

Сортировка

Писать свою не нужно — в стандартной библиотеке уже есть оптимизированные. Но полезно знать:

  • Пузырьком — учебная, O(n²), на практике не используется.
  • QuickSort — O(n log n) в среднем, но O(n²) в худшем.
  • MergeSort — стабильные O(n log n), используется для внешней сортировки.
  • Timsort — гибрид, встроен в Python и Java.

Рекурсия и динамическое программирование

Рекурсия — когда функция вызывает саму себя. Пример: факториал.

def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)

Динамическое программирование (DP) — это когда ты решаешь сложную задачу через подзадачи и запоминаешь их результаты, чтобы не считать заново. Классика — числа Фибоначчи, задача о рюкзаке, редакционное расстояние.

Что учить в первую очередь

  1. Big O — чтобы понимать, какой код быстрый, а какой нет.
  2. Массив, хеш-таблица, стек, очередь — покрывают 80% практических задач.
  3. Бинарный поиск и сортировки — база для собеседований.
  4. Деревья и графы — когда освоишь базу.
  5. Динамическое программирование — для подготовки к серьёзным собеседованиям.

Как тренироваться

Лучшие ресурсы:

  • LeetCode — стандарт для собеседований. Начни с Easy, иди по тегам.
  • Codewars — более игровой подход, задачи разной сложности.
  • Stepik / Coursera — курсы по алгоритмам с теорией.
  • Книга «Грокаем алгоритмы» — с картинками, для новичков.
  • Книга «Алгоритмы. Построение и анализ» (Кормен) — уже для серьёзного уровня.
Не пытайся выучить все структуры сразу. Возьми одну, разберись, реши 5–10 задач — и только потом переходи к следующей.

Нужно ли это в реальной работе

В веб-разработке ты не будешь писать сбалансированное дерево вручную. Но:

  • понимание Big O поможет выбрать между циклом и хеш-таблицей;
  • знание очередей пригодится в фоновых задачах и обработке событий;
  • графы нужны для построения зависимостей, маршрутов, рекомендаций;
  • на собеседованиях в крупные компании спросят обязательно.

Итого: учить стоит. Не как самоцель, а как инструмент мышления.

Итог

Алгоритмы и структуры данных — фундамент. Начни с Big O и базовых структур: массива, хеш-таблицы, стека, очереди. Потом добавь деревья, графы и базовые алгоритмы. Тренируйся на задачах — без практики теория не закрепляется.
