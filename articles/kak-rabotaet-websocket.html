Как работает WebSocket — real-time связь между браузером и сервером

14 апреля 2026 • 10 мин чтения
Поделиться:

Если делаешь чат, биржевой терминал, онлайн-игру или просто уведомления в реальном времени — обычный HTTP будет мешать. Сервер не может «сам» отправить данные клиенту. Для таких задач есть WebSocket.

Проблема HTTP

HTTP работает по схеме «запрос-ответ». Клиент спрашивает — сервер отвечает. Сервер не может первым обратиться к клиенту.

Что делать, если нужно получать сообщения из чата в реальном времени? Есть три плохих способа.

1. Постоянные запросы (polling)

Клиент каждую секунду спрашивает: «Есть новые сообщения?». В 99% случаев ответ пустой — а трафик тратится.

// Каждую секунду — новый HTTP-запрос
setInterval(function() {
  fetch('/api/messages?since=' + lastId)
    .then(function(r) { return r.json(); })
    .then(function(messages) {
      messages.forEach(showMessage);
    });
}, 1000);

2. Длинные запросы (long polling)

Клиент отправляет запрос и держит его открытым, пока сервер не ответит. Как только ответ пришёл — сразу новый запрос. Уже лучше, но нагрузка огромная.

3. Server-Sent Events

Сервер отправляет поток данных в одну сторону — от себя к клиенту. Работает для новостных лент, но не для чата: клиент не может так же легко отвечать.

Что такое WebSocket

WebSocket — это протокол для двустороннего постоянного соединения. Один раз установил — и клиент, и сервер могут отправлять данные друг другу в любой момент.

WebSocket — это как телефонный разговор: соединились один раз и говорите, пока кто-то не положит трубку. HTTP — как переписка письмами: каждый раз нужно новое сообщение.

Как устанавливается соединение

Соединение начинается с обычного HTTP-запроса — это называется handshake.

  1. Клиент отправляет HTTP-запрос со специальным заголовком Upgrade: websocket.
  2. Сервер отвечает кодом 101 Switching Protocols — «согласен, переключаемся».
  3. Дальше то же TCP-соединение используется для общения по правилам WebSocket.

После handshake начинается двусторонний обмен короткими сообщениями — кадрами.

Клиент на JavaScript

// Открываем соединение с сервером
var socket = new WebSocket('wss://example.com/chat');

// Соединение установлено
socket.onopen = function() {
  console.log('Соединение открыто');
  socket.send('Привет, сервер!');
};

// Пришло сообщение от сервера
socket.onmessage = function(event) {
  console.log('Сообщение:', event.data);
};

// Ошибка или закрытие
socket.onerror = function(error) {
  console.error('Ошибка:', error);
};

socket.onclose = function() {
  console.log('Соединение закрыто');
};

// Отправить данные в любой момент
function sendMessage(text) {
  if (socket.readyState === WebSocket.OPEN) {
    socket.send(text);
  }
}

Обрати внимание на wss:// — это защищённая версия WebSocket, как HTTPS для HTTP. Всегда используй её в проде.

Сервер на Python

Самый простой способ — библиотека websockets.

import asyncio
import websockets

# Множество активных клиентов
clients = set()

async def handler(websocket):
    # Регистрируем нового клиента
    clients.add(websocket)
    print('Подключился клиент, всего:', len(clients))

    try:
        async for message in websocket:
            # Пришло сообщение — рассылаем всем клиентам
            print('Получено:', message)
            for client in clients:
                await client.send(message)
    finally:
        # Клиент отключился — убираем его
        clients.remove(websocket)
        print('Клиент отключился, осталось:', len(clients))

async def main():
    # Запускаем сервер на порту 8765
    async with websockets.serve(handler, 'localhost', 8765):
        print('Сервер запущен на ws://localhost:8765')
        await asyncio.Future()   # работаем вечно

asyncio.run(main())

Это минимальный чат. Все клиенты получают все сообщения — а сервер живёт одним бесконечным циклом.

Что важно знать про соединение

Обрыв связи

WebSocket-соединение может разорваться: пропал интернет, сервер перезапустился, мобильное устройство уснуло. Клиент должен уметь переподключаться автоматически.

function connect() {
  var socket = new WebSocket('wss://example.com/chat');

  socket.onopen = function() {
    console.log('Соединение установлено');
  };

  socket.onclose = function() {
    console.log('Соединение закрыто, переподключаемся через 3 секунды');
    // Через 3 секунды пробуем снова
    setTimeout(connect, 3000);
  };
}

connect();

Heartbeat (пинг-понг)

Чтобы соединение не закрылось само по таймауту, клиент периодически отправляет «пинг» — короткое пустое сообщение. Сервер отвечает «понг».

// Каждые 30 секунд — проверка, что соединение живо
setInterval(function() {
  if (socket.readyState === WebSocket.OPEN) {
    socket.send(JSON.stringify({ type: 'ping' }));
  }
}, 30000);

Где применяется WebSocket

  • Чаты и мессенджеры. Мгновенная доставка сообщений.
  • Онлайн-игры. Позиции игроков обновляются десятки раз в секунду.
  • Биржевые терминалы. Курсы акций в реальном времени.
  • Совместное редактирование. Google Docs, Figma — все изменения сразу видны.
  • Уведомления. Push-сообщения без перезагрузки страницы.
  • Стриминг данных. Логи, метрики, телеметрия.

Альтернативы

WebSocket — не единственный вариант для real-time. Есть ещё:

  • Socket.IO. Библиотека поверх WebSocket с автоматическим fallback на long polling, если WebSocket не работает. Удобна, но добавляет вес.
  • Server-Sent Events (SSE). Односторонний поток от сервера к клиенту. Проще WebSocket, работает поверх HTTP.
  • WebRTC. Прямое соединение между браузерами — для видео и аудио.
  • gRPC streaming. Двусторонний поток для микросервисов.

Частые ошибки

  • Забыть про переподключение. Соединение оборвётся — и без авто-реконнекта клиент перестанет получать данные.
  • Открывать много сокетов. Один сокет на вкладку — достаточно. Не создавай новый на каждый компонент.
  • Забыть про wss. В проде — только защищённое соединение.
  • Хранить состояние только в памяти сервера. При перезапуске всё пропадёт. Для серьёзных систем состояние держат в Redis или базе.

Итог

WebSocket — протокол для двусторонней связи в реальном времени. Устанавливается один раз через HTTP-handshake, дальше обмен идёт напрямую. Идеален для чатов, игр, бирж и уведомлений. Требует аккуратности: переподключение, heartbeat, wss. Для обычных сайтов с загрузкой страниц — не нужен, там HTTP достаточно.
