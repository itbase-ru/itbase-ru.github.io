Как работает браузер: DOM, парсинг и рендеринг

19 марта 2026 • 11 мин чтения
Поделиться:

Ты открываешь страницу — она появляется за долю секунды. За это время браузер делает работу, на которую у человека ушёл бы час. Разберём по шагам, что там происходит.

Общая картина

  1. Браузер получает HTML-файл по сети.
  2. Разбирает его и строит DOM — объектную модель документа.
  3. Читает CSS и строит CSSOM — объектную модель стилей.
  4. Объединяет их в рендер-дерево.
  5. Считает, где что находится — layout.
  6. Рисует пиксели — paint.

Всё это — за миллисекунды. Разберём каждый этап.

Этап 1. Загрузка

Браузер отправляет запрос на сервер, получает ответ — обычно HTML-текст. Начинает читать его сверху вниз, строя структуру. Если встретил <link href="style.css"> — идёт за CSS. Если <script src="app.js"> — идёт за JS.

Вот почему скрипты обычно ставят в конце <body>: пока браузер их скачает и выполнит, он не может строить DOM дальше. Если скрипт в начале — страница «замирает».

Этап 2. DOM — что это

DOM (Document Object Model) — это представление HTML-страницы в виде дерева объектов. Каждый тег превращается в узел, у которого есть свойства и дети.

Пример HTML:

<body>
  <h1>Привет</h1>
  <p>Это <strong>текст</strong>.</p>
</body>

Превратится в такое дерево:

body
├── h1
│   └── "Привет"
└── p
    ├── "Это "
    └── strong
        └── "текст"

Именно с этим деревом работает JavaScript. Когда ты пишешь document.querySelector('h1') — ты ищешь узел в DOM.

Этап 3. CSSOM — стили в виде дерева

CSS тоже превращается в дерево. У каждого правила — селектор и свойства. Браузер идёт сверху вниз, накапливает стили и понимает, какие правила применятся к какому узлу.

Важный момент: CSS **блокирует рендеринг**. Пока браузер не получит все стили — он не начнёт рисовать. Иначе пользователь увидел бы «голый» HTML, который через секунду перерисуется в красивый вид. Это называется FOUC — flash of unstyled content.

Этап 4. Рендер-дерево

DOM и CSSOM объединяются в рендер-дерево — структуру, где у каждого узла есть и содержимое, и стили. Только то, что будет отрисовано.

Например, если у элемента display: none — он в рендер-дерево не попадёт. А visibility: hidden попадёт — просто будет невидимым.

Этап 5. Layout — где что находится

Браузер обходит рендер-дерево и считает точные координаты каждого элемента: где левый верхний угол, какие размеры, как элементы расположены относительно друг друга.

Именно на этом этапе «вылезают» баги типа «этот блок съехал вниз». Рендер-дерево говорит «это абзац», layout решает «этот абзац на 100 пикселей ниже заголовка, шириной 800».

Этап 6. Paint — рисуем пиксели

Последний этап. Браузер «раскрашивает» каждый прямоугольник из layout: заливает фон, рисует границы, текст, тени. Потом склеивает слои — и ты видишь готовую страницу.

Что происходит при изменениях

Когда ты на JavaScript что-то меняешь — браузер пересчитывает только то, что затронуто.

Что меняешьЧто пересчитываетсяСкорость
Цвет, opacityТолько paintБыстро
Размер, положениеLayout + paintМедленнее
Добавил элементDOM + layout + paintМедленно

Поэтому продвинутые анимации делают через transform и opacity — они не трогают layout и работают быстро.

Что такое reflow и repaint

  • Reflow (пересчёт layout). Браузер пересчитывает позиции. Дорогая операция. Вызывается, когда ты меняешь размеры, отступы, шрифт.
  • Repaint (перерисовка). Просто меняются цвета. Дешевле. Вызывается при смене цвета, фона.

Правило: минимизируй reflow. Например, не меняй стили по одному в цикле — сначала подготовь, потом примени разом.

Практические выводы

  • Скрипты в конце body. Так браузер быстрее построит DOM.
  • CSS в head. Чтобы не было FOUC — пользователь сразу увидит оформленную страницу.
  • Анимации — через transform и opacity. Не через left/top и width/height.
  • Минимум DOM-операций. Собрал HTML строкой и вставил одним движением — быстрее, чем добавлять 100 узлов по одному.

Что важно запомнить

  • Браузер строит DOM, CSSOM, рендер-дерево.
  • Порядок: парсинг → layout → paint.
  • Reflow дороже repaint.
  • Скрипты не должны блокировать построение DOM.
  • С изменением одного элемента браузер пересчитывает не всё дерево, а только нужное.
