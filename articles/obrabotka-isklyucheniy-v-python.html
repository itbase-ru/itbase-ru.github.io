Обработка исключений в Python — try, except, finally

24 апреля 2026 • 11 мин чтения
Поделиться:

Программа всегда может столкнуться с неожиданностью: файл не найден, пользователь ввёл не то, сеть пропала. Если не обрабатывать ошибки — программа упадёт. Python даёт удобный механизм для этого — исключения.

Что такое исключение

Исключение (exception) — это сигнал, что во время выполнения что-то пошло не так. Python «бросает» исключение, и если его никто не поймал — программа аварийно завершается.

# Программа упадёт с ошибкой
result = 10 / 0
# ZeroDivisionError: division by zero

numbers = [1, 2, 3]
print(numbers[10])
# IndexError: list index out of range

Обе ошибки — исключения. Python сообщает, что именно произошло, и останавливает выполнение, если никто ошибку не перехватил.

try / except — базовый синтаксис

Чтобы программа не падала, опасный код оборачивают в try. Если внутри возникает ошибка — управление переходит в except.

try:
    result = 10 / 0
    print('Результат:', result)
except ZeroDivisionError:
    print('На ноль делить нельзя!')

print('Программа продолжает работу')

Программа выведет: «На ноль делить нельзя!» «Программа продолжает работу» — и не упадёт.

Ловить разные ошибки отдельно

Можно обрабатывать разные типы исключений по-разному:

try:
    numbers = [1, 2, 3]
    index = int(input('Какой индекс показать? '))
    print(numbers[index])
except ValueError:
    print('Это не число')
except IndexError:
    print('Такого индекса нет в списке')

Python сам определит, какое исключение возникло, и вызовет соответствующий блок except.

Получить объект ошибки

Иногда надо знать подробности ошибки. Синтаксис as сохраняет объект исключения:

try:
    result = 10 / 0
except ZeroDivisionError as error:
    print('Ошибка:', error)
    print('Тип:', type(error).__name__)

Из объекта можно получить текст сообщения, тип, трассировку — всё, что полезно для логов.

Ловить всё подряд

Можно ловить любое исключение через except Exception:

try:
    result = do_something_risky()
except Exception as error:
    print('Что-то пошло не так:', error)

Это работает, но не рекомендую использовать в обычном коде. Ловить всё подряд — значит скрывать реальные проблемы. Если ты не знаешь, что именно может упасть, — узнай и лови точечно.

Лови конкретные исключения. Ловить всё подряд — значит маскировать баги, которые потом будет сложно отыскать.

else и finally

Полная форма try имеет четыре блока:

  • try — опасный код.
  • except — что делать при ошибке.
  • else — что делать, если ошибки не было.
  • finally — что делать в любом случае.
try:
    f = open('data.txt', 'r')
    content = f.read()
except FileNotFoundError:
    print('Файл не найден')
else:
    # Сюда попадём только если ошибки не было
    print('Прочитано символов:', len(content))
finally:
    # Сюда попадём в любом случае — была ошибка или нет
    print('Работа с файлом завершена')

finally — идеальное место для закрытия файлов, соединений, освобождения ресурсов.

Собственные исключения

Можно создавать свои классы исключений. Это делает код понятнее — по типу ошибки сразу видно, что пошло не так.

# Своё исключение — наследник Exception
class InsufficientFundsError(Exception):
    pass

class BankAccount:
    def __init__(self, balance):
        self.balance = balance

    def withdraw(self, amount):
        if amount > self.balance:
            # Бросаем наше исключение
            raise InsufficientFundsError(
                'Недостаточно средств: нужно ' + str(amount) +
                ', доступно ' + str(self.balance)
            )
        self.balance -= amount
        return amount

# Использование
account = BankAccount(1000)

try:
    account.withdraw(5000)
except InsufficientFundsError as error:
    print('Ошибка:', error)

Своё исключение превращает непонятное «что-то упало» в конкретную бизнес-ошибку.

Ключевое слово raise

raise — бросает исключение вручную. Три способа применения:

# 1. Бросить новое исключение
raise ValueError('Некорректное значение')

# 2. Пробросить дальше уже пойманное
try:
    do_something()
except SomeError:
    log_error()
    raise   # пробрасываем то же исключение выше

# 3. Заменить на другое
try:
    do_something()
except SomeError as error:
    raise RuntimeError('Сбой обработки') from error

Третий вариант хорош тем, что сохраняет связь с исходной ошибкой — в трассировке будет видно обе.

Контекстные менеджеры

Конструкция with — удобная альтернатива try/finally для работы с ресурсами. Она сама закроет файл, даже если внутри произойдёт ошибка:

# Плохо — надо не забыть закрыть
f = open('data.txt')
try:
    content = f.read()
finally:
    f.close()

# Хорошо — with закроет сам
with open('data.txt') as f:
    content = f.read()
# После выхода из блока файл закрыт

Работает с любыми объектами, у которых есть методы __enter__ и __exit__. Например, с соединениями базы данных, блокировками, временными файлами.

Практический пример: безопасное чтение числа

def read_number(prompt):
    'Просит пользователя ввести число, повторяет при ошибке'
    while True:
        try:
            value = int(input(prompt))
            return value
        except ValueError:
            print('Это не число. Попробуй ещё раз.')

age = read_number('Сколько тебе лет? ')
print('Через 10 лет будет:', age + 10)

Пользователь может ошибаться сколько угодно — программа не упадёт. Такой паттерн используется везде, где ввод от человека.

Частые ошибки

  • Ловить всё через except Exception. Скрывает баги. Лови конкретные типы.
  • Пустой except: без переменной. «Проглотить» ошибку молча — худший вариант. В логах должна остаться информация.
  • Слишком широкий try. Оборачивай только опасный код, а не 50 строк вокруг.
  • Не закрыть ресурс. Всегда используй with или finally.
  • Игнорировать ошибку. Если не знаешь, что делать с исключением — не лови его. Пусть поднимется выше, где с ним разберутся осмысленно.

Как читать трассировку

Когда исключение не поймано, Python печатает трассировку. Читать её надо снизу вверх:

Traceback (most recent call last):
  File "app.py", line 10, in <module>
    process_user(user)
  File "app.py", line 6, in process_user
    return user['email']
KeyError: 'email'

Снизу — тип ошибки (KeyError: 'email'). Выше — цепочка вызовов. Самое важное: первая строка файла с ошибкой — та, где реально что-то сломалось.

Итог

Исключения — способ не дать программе падать и осмысленно обрабатывать ошибки. Основные конструкции: try, except, else, finally. Лови конкретные типы, не всё подряд. Создавай свои исключения для бизнес-ошибок. Работай с ресурсами через with. Не молчи, если ошибка случилась — пиши в лог. И не забывай: если не знаешь, что делать с ошибкой — не лови её.
